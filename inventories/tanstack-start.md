# TanStack Start (React) — feature inventory
Version documented: **1.169+ (v1, stable)** — `S:migrate-from-release-candidate.md` says "`@tanstack/react-start` 1.169 is the first stable release"; `S:overview.md` banner "TanStack Start is stable"; comparison pages say "Checked September 11, 2026". No later version number appears in the docs, so the docs describe ≥1.169 (exact patch unknown). Router docs are v1 (several "removed in v2" notes). · Docs commit: 2026-11-03
Context: React 18/19 (RSC and Bun guidance require React 19); a Solid flavor (`@tanstack/solid-start`) shares most docs · bundler: **Vite 8 (required when using Vite)** or **Rsbuild** (Rsbuild 2+ for RSC) via `tanstackStart()` plugin (`@tanstack/react-start/plugin/vite` | `/plugin/rsbuild`) · server engine: Start's own WinterCG fetch handler (`createStartHandler` / `createServerEntry`, `export default { fetch }`); Nitro (`nitro/vite`) is the documented deploy layer for Node/Vercel/Railway/Bun · default runtime: Node (Nitro output `.output/server/index.mjs`); Cloudflare Workers and Netlify via their own Vite plugins.

Path abbreviations used in citations: **`S:`** = `docs/start/framework/react/`, **`R:`** = `docs/router/`, **`SS:`** = `docs/start/framework/solid/`.

Status summary (explicit in docs):
- **Stable**: routing, loaders/beforeLoad/router cache, server functions, middleware (request + function), server routes, selective SSR, SPA mode, static prerendering, streaming SSR, import protection, head management.
- **Experimental**: React Server Components (`S:guide/server-components.md`, "will remain so into early v1"), Deferred hydration `<Hydrate>` (`S:guide/deferred-hydration.md`), Static Server Functions (`S:guide/static-server-functions.md`), Early Hints (`S:guide/early-hints.md`), CSS inlining (`S:guide/css-styling.md`), `transformAssets` CDN rewriting (`S:guide/cdn-asset-urls.md`), `serverFns.generateFunctionId` (`S:guide/server-functions.md`), OpenTelemetry recipe (`S:guide/observability.md`), new `useBlocker` API (`R:api/router/useBlockerHook.md`), `params.parse` returning `false` (`R:api/router/RouteOptionsType.md`).
- **Deprecated** (router): `parseParams`/`stringifyParams`, `preSearchFilters`/`postSearchFilters`, `NotFoundRoute`/`notFoundRoute`, `notFound({ global })`, `opts.navigate` in loader/beforeLoad, `<ScrollRestoration/>` component, `defer()` (unnecessary), `useBlocker({ blockerFn, condition })`, `MatchRouteOptions.caseSensitive`, `*` splat key (removed in v2).
- **Removed at 1.169**: `@tanstack/nitro-v2-vite-plugin` (use `nitro()` from `nitro/vite`), `useSession` (use a session library), `.inputValidator()` (now `.validator()`) (`S:migrate-from-release-candidate.md`).

## 1. Routing

- **Route definition (file-based / code-based)**: **Supported — both, plus "virtual file routes".** Start uses file-based routing by default: route files live in `src/routes`, each exports `export const Route = createFileRoute('/posts/$postId')({...})`. The path string passed to `createFileRoute` is **written and maintained automatically** by the bundler plugin / Router CLI when files are created/moved/renamed. A generated `src/routeTree.gen.ts` (route tree + TS registration helpers) is produced when running dev/build. `src/router.tsx` must export `getRouter()` that **returns a new router instance on every call** (Start creates one per SSR request). Code-based routing (`createRootRoute`, `createRoute({ getParentRoute, path | id, ... })`, `.addChildren([...])`) is supported but "not recommended for most applications". **Virtual file routes** (`@tanstack/virtual-file-routes`: `rootRoute()`, `route(path, file, children)`, `index(file)`, `layout(file, children)`, `physical(urlPrefix, dir)`) build the tree in code while pointing at real files; configured via `virtualRouteConfig` (bundler plugin) or `tsr.config.json`; can be mixed into file-based trees. Status: stable. Source: `S:guide/routing.md`, `R:routing/file-based-routing.md`, `R:routing/code-based-routing.md`, `R:routing/virtual-file-routes.md`
  - **File naming conventions** (`R:routing/file-naming-conventions.md`, `R:routing/routing-concepts.md`):

    | Token / pattern | Meaning |
    |---|---|
    | `__root.tsx` | Root route; must sit at root of `routesDirectory`; no path; always matched; component always rendered (renders `<html>` shell in Start) |
    | `.` separator | Flat nesting: `blog.post.tsx` is child of `blog`; flat and directory (`/`) forms can be mixed freely |
    | `$name` | Dynamic segment → `params.name` |
    | `$` (alone) | Splat → `params._splat` (v1 also exposes `*` key, removed in v2) |
    | `{-$name}` | Optional segment (e.g. `posts.{-$category}.tsx` matches `/posts` and `/posts/tech`) |
    | `pre{$name}suf` | Prefix/suffix params: `post-{$postId}`, `{$fileName}[.]txt`, combinable, also with splats (`storage-{$id}/$`) and optional params |
    | `_name` prefix | Pathless layout route (ID after `_` required; can't contain a `$` param) |
    | `name_` suffix | Non-nested ("break-out") route: `posts_.$postId.edit.tsx` renders outside `posts` layout |
    | `-name` prefix | Excluded from route tree (colocate components/utils) |
    | `(group)` dir | Route group; no URL or tree effect |
    | `[x]` | Escape special chars: `script[.]js.tsx` → `/script.js` |
    | `index` | Index route (token configurable via `indexToken`, string or regex) |
    | `route.tsx` | Directory route file (`blog/post/route.tsx` ≡ `blog.post.tsx`; token configurable via `routeToken`) |
    | `*.lazy.tsx` | Manual code-split companion (`createLazyFileRoute`) |

  - **Route-generator options** (`R:api/file-based-routing.md`): `routesDirectory` (`./src/routes`), `generatedRouteTree` (`./src/routeTree.gen.ts`), `virtualRouteConfig` (undefined), `routeFilePrefix` (''), `routeFileIgnorePrefix` (`-`), `routeFileIgnorePattern` (undefined), `routeToken` (`route`), `indexToken` (`index`), `quoteStyle` (`single`), `semicolons` (false), `autoCodeSplitting` (false in Router plugin; "v2 will default to true"; error with esbuild), `disableTypes` (false; emits `.js`), `addExtensions` (false | true | `'js'`), `disableLogging` (false), `routeTreeFileHeader/Footer`, `enableRouteTreeFormatting` (true), `tmpDir` (`.tanstack/tmp` or `TSR_TMP_DIR`). Warning: don't set prefixes to collide with naming tokens. How these are passed through `tanstackStart()` is **not shown in Start docs** (from memory: `tanstackStart({ router: {...} })`, unverified).
- **Nested layouts**: **Supported.** Any route with children is a layout; it renders `<Outlet/>` (route `component` defaults to `<Outlet/>`; `defaultComponent` router option). Layout routes can own a loader, `beforeLoad`, search validation, context, pending/error/notFound fallbacks for descendants. Re-render/remount behavior: a route component that stays active across navigation is **not remounted** by default; `remountDeps(({ routeId, search, params, loaderDeps }) => any)` / router `defaultRemountDeps` remounts when the (JSON-serializable) return value changes. Lifecycle callbacks `onEnter`/`onStay`/`onLeave(match)` (not dispatched for background reloads; routes below an error/notFound boundary don't "enter"). Root route may define `shellComponent` (always SSR'd `<html>` wrapper around root `component`, `errorComponent`, `notFoundComponent`). Source: `R:routing/routing-concepts.md`, `R:api/router/RouteOptionsType.md`, `S:guide/selective-ssr.md`
- **Dynamic, optional, catch-all segments**: **Supported** (see table). Params parsed once are available to all child routes. Matching order is automatic regardless of definition order: index → static (most specific first) → dynamic (longest → shortest) → splat; optional-param routes rank below exact matches (`/posts/featured` beats `/posts/{-$category}`). Param validation/parsing: `params.parse(raw) => TParams | false` and `params.stringify(params)`; throwing puts route in error state; **experimental**: returning `false` skips the route so matching continues; `params.priority` (number, default 0) orders competing `params.parse` candidates (higher first; static still beats dynamic). `caseSensitive` (route or router, default false). `pathParamsAllowedCharacters` (`; : @ & = + $ ,`, router-creation-only). Path-param-based i18n via optional prefix `{-$locale}` documented. Source: `R:guide/path-params.md`, `R:routing/route-matching.md`, `R:api/router/RouteOptionsType.md`, `R:api/router/RouterOptionsType.md`
- **Route groups / pathless layouts**: **Supported.** `(folder)` = purely organizational; `_pathless.tsx` = wraps children with component/logic without a URL segment (code-based: `id` instead of `path`). Relative navigation from inside a pathless layout resolves from its parent. In server routes, pathless layouts can attach middleware to a group and break-out (`_` suffix) routes escape parent middleware. Source: `R:routing/routing-concepts.md`, `S:guide/server-routes.md`, `R:guide/navigation.md`
- **Parallel routes / intercepting routes**: **Not supported.** `R:guide/parallel-routes.md` is a stub ("We haven't covered this yet. Stay tuned!"); Router comparison table marks "Parallel Routes 🛑"; Next.js migration guide: parallel/intercepting routes "need individual mapping" and the reference does not reproduce them. **Partial substitute: route masking** — navigate to one route while displaying another URL (modal pattern: real `/photo/5/modal`, displayed `/photos/5`). APIs: `mask` option on `Link`/`navigate` (a `ToOptions` object), or declarative `routeMasks: [createRouteMask({ routeTree, from, to, params, ..., unmaskOnReload })]` on the router. Mechanism: stored in `location.state.__tempLocation`; real location kept as `location.maskedLocation`; URL is unmasked when copied/shared (state lost); **not** unmasked on local reload by default; `unmaskOnReload` precedence: router default (false) < mask-level < per-navigation. Source: `R:guide/route-masking.md`, `R:comparison.md`, `S:migrate-from-next-js.md`
- **Typed links and typed route params**: **Supported (inferred, no extra codegen beyond `routeTree.gen.ts`).** Types flow via declaration merging on the `Register` interface; `to`, `params`, `search`, `hash` are checked/autocompleted; required params/search enforced. `from` narrows relative paths and types; without `from`, only absolute paths autocomplete. `strict: false` on hooks gives loosened unions. Route objects expose `.to`/`.fullPath` for refactor-safe references; `Route.redirect(...)`/`getRouteApi(id).redirect(...)` auto-fill `from`. Utilities: `linkOptions()`, `createLink(Component)` (custom typed link wrappers, e.g. React Aria/MUI), `ValidateLinkOptions`, `ValidateLinkOptionsArray`, `ValidateRedirectOptions`, `ValidateNavigateOptions`. Source: `R:guide/type-safety.md`, `R:guide/type-utilities.md`, `R:guide/custom-link.md`, `R:api/router/redirectFunction.md`
  - **`<Link>` props** (`R:api/router/LinkPropsType.md`, `LinkOptionsType.md`, `NavigateOptionsType.md`, `ToOptionsType.md`, `ActiveLinkOptionsType.md`, `R:guide/navigation.md`):

    | Prop | Values / default | Behavior |
    |---|---|---|
    | `to` | absolute or relative route path; `.`/`..` | Destination; never interpolate params/search/hash into it. `to="."` + `search` updates current route's search loosely typed |
    | `from` | route id/path | Origin for relative resolution + typing; default = current active location for runtime resolution, root for types |
    | `params` | object \| `(prev) => next` \| `true` | Only way to fill `$params`; function form preserves current params; setting an optional param to `undefined` removes the segment |
    | `search` | object \| `(prev) => next` \| `true` | JSON-serialized; passes through search middlewares |
    | `hash` | string \| `(prev) => string` \| `true` | — |
    | `state` | object \| `(prev) => next` \| `true` | Stored in history state (not URL) |
    | `mask` | `ToMaskOptions` | Route masking (see above) |
    | `replace` | `false` | `history.replace` instead of push |
    | `resetScroll` | `true` | Reset to 0,0 (or skip restoration when `false`) |
    | `hashScrollIntoView` | `true` \| `ScrollIntoViewOptions` | Scroll element whose id matches hash |
    | `viewTransition` | `false` \| `true` \| `{ types }` | Wraps update in `document.startViewTransition` |
    | `ignoreBlocker` | `false` | Bypass navigation blockers |
    | `reloadDocument` | `false` | Full page load instead of SPA navigation |
    | `href` | string | Use instead of `to` for prebuilt/external URL |
    | `target` | anchor target | Standard |
    | `activeOptions` | `{ exact: false, includeHash: false, includeSearch: true, explicitUndefined: false }` | Default: active if target pathname is a prefix of current path and provided search params inclusively match; hash ignored |
    | `activeProps` / `inactiveProps` | props object \| `() => props` | Override other props; `style` merged, `className` concatenated |
    | `preload` | `false` \| `'intent'` \| `'viewport'` \| `'render'`; default = router `defaultPreload` (`false`) | See prefetching |
    | `preloadDelay` | ms; default router `defaultPreloadDelay` = 50 | Delays focus/hover/viewport preloads; touch is immediate; cancelled if intent ends |

    | `children` | node \| `({ isActive }) => node` | Render-prop exposes active state |
    | ...all `<a>` attrs | | |

    Renders a real `<a href>` (cmd/ctrl-click works); adds `data-status="active"` when active. Absolute URLs with protocols outside router `protocolAllowlist` (default `http: https: mailto: tel:`) are rejected for `Link`, `navigate`, `redirect` (XSS guard). Output URL rewrites are applied to `href`; if a rewrite changes origin, `Link` renders a plain anchor (hard navigation). Source: `R:api/router/RouterOptionsType.md`, `R:guide/url-rewrites.md`
- **Search-param handling**: **Supported — typed and validated (a signature feature).** Default serializer is **JSON-first**: top level is URLSearchParams-compatible, numbers/booleans preserved as types, nested arrays/objects become URL-safe JSON strings; parsed results use **structural sharing** (unchanged keys keep object identity). Validation via route `validateSearch`: a function `(raw: Record<string, unknown>) => T`, an object with `.parse`, or any **Standard Schema** (Zod v4, Valibot 1.0, ArkType 2.0-rc, Effect Schema) directly; Zod v3 via `@tanstack/zod-adapter` `zodValidator(schema | { schema, input, output })` + `fallback(schema, value)`. Input vs output types are inferred separately so `.default()` fields become optional on `<Link search>`; manual tag `SearchSchemaInput`. If validation throws: route enters error state, `onError` fires with `error.routerCode === 'VALIDATE_SEARCH'`, `errorComponent` renders (docs recommend `.catch()` fallbacks instead). `validateSearch` must be deterministic/side-effect-free. Child routes inherit and merge parent search schemas. **Loaders cannot read `search` directly**; they must declare `loaderDeps: ({ search }) => ({...})` (becomes cache key; deep-compared). **Search middlewares** `search.middlewares: [({ search, next }) => ...]` transform search when building links and after validation on navigation; built-ins `retainSearchParams(true | keys[])`, `stripSearchParams(true | keys[] | defaultsObject)` (deep-equal default stripping). Router `search.strict` (default `false`: unknown params kept; `true`: removed). Custom serialization via router `parseSearch`/`stringifySearch` with helpers `parseSearchWith`/`stringifySearchWith` (base64, query-string, JSURL2, Zipson examples; non-UTF8-safe encoding helpers provided). Reading: `Route.useSearch()`, `useSearch({ from, strict, select, structuralSharing, shouldThrow })`, `getRouteApi('/x').useSearch()`. Writing: `<Link search>`, `navigate({ search })`, `router.navigate`, `<Navigate search>`. Source: `R:guide/search-params.md`, `R:guide/custom-search-param-serialization.md`, `R:api/router/retainSearchParamsFunction.md`, `R:api/router/stripSearchParamsFunction.md`, `R:api/router/useSearchHook.md`
- **Programmatic navigation**: **Supported.** `useNavigate({ from })` → `navigate(NavigateOptions)` (recommended only for side-effect navigation; prefer `Link` for user-interactive elements); `<Navigate .../>` navigates on mount (client-only redirect, "not a substitute for server-aware redirects"); `router.navigate()` usable anywhere the router instance is available (outside React too); `redirect()` thrown from `beforeLoad`/`loader`/server functions for server-aware redirects. On the server, `router.navigate()` and `router.commitLocation()` are **no-ops** (server history is fixed to the request URL). Route matching checks: `useMatchRoute()` → `matchRoute({ to, pending, includeSearch, fuzzy })` (subscribes to state), `<MatchRoute pending>{(match)=>...}</MatchRoute>`, `router.matchRoute(dest, opts)` (non-subscribing). Also `useCanGoBack`, `useLocation`, `useRouter`. Navigation blocking: `useBlocker({ shouldBlockFn({current, next, action}) => boolean|Promise, disabled=false, enableBeforeUnload=true | fn, withResolver=false })` returning `{ status: 'idle'|'blocked', next, current, action, proceed, reset }` when `withResolver`; `<Block>` component with same render-prop state; blockers run sequentially, any `false` cancels; browser unload uses `beforeunload` (new API **experimental**; `blockerFn`/`condition` deprecated). Source: `R:guide/navigation.md`, `R:guide/navigation-blocking.md`, `R:api/router/useBlockerHook.md`, `R:guide/ssr.md`
- **Prefetching (strategies)**: **Supported — prefetches both code and data.** Strategies: `'intent'` (hover/focus after delay, `touchstart` immediately), `'viewport'` (IntersectionObserver), `'render'` (as soon as the Link renders), `false`. Router default `defaultPreload: false` (Start template does not change it); per-link `preload`. Delay `defaultPreloadDelay` 50ms (cancelled if focus/hover ends or link leaves viewport). A preload runs the route chunk load, **every matched route's `beforeLoad`** (with `preload: true`, `cause: 'preload'`) and **`loader`** (skipped if route `preload: false`). Preloaded loader data: fresh for `preloadStaleTime`/`defaultPreloadStaleTime` (**30s**), retained for `preloadGcTime`/`defaultPreloadGcTime` (**5 min**, pruned at a later cache reconciliation, not on a timer). The "speculative lane is never promoted into router state": a later navigation **re-runs its own `beforeLoad` chain** (never reuses preload's beforeLoad context, redirects, errors or notFound results) but **can reuse settled loader data or join in-flight loader work**; once navigation accepts the data, `staleTime` governs. Manual: `router.preloadRoute(NavigateOptions)` returns the speculative match lane (errors/notFound represented in the lane rather than rejecting; `undefined` on cancellation); `router.loadRouteChunk(route)` fetches code only. With an external cache set `defaultPreloadStaleTime: 0`. Source: `R:guide/preloading.md`, `R:api/router/RouterOptionsType.md`, `R:api/router/RouteOptionsType.md`
- **Scroll restoration**: **Supported.** Router option `scrollRestoration: true` (enabled in Start's template router) monitors scroll, caches positions for `window`, `body` and registered scrollable areas, and restores **before paint** after navigation. Options: `getScrollRestorationKey(location)` (default `location.state.__TSR_key`; legacy `state.key` before v1.121.34, removed in next major), `scrollToTopSelectors` (CSS selectors or element-returning functions, in addition to `window` which can't be disabled), `scrollRestorationBehavior: 'smooth' | 'instant' | 'auto'`. Opt-out per navigation: `resetScroll: false` on `Link`, `navigate`, `redirect`. Manual/virtualized lists: `useElementScrollRestoration({ id } | { getElement })` + `data-scroll-restoration-id` attribute. Hash scrolling default on (`defaultHashScrollIntoView: true` or `ScrollIntoViewOptions`). `<ScrollRestoration/>` component deprecated. Comparison table claims element + async scroll restoration. Source: `R:guide/scroll-restoration.md`, `S:guide/routing.md`
- **View transitions**: **Supported.** Router `defaultViewTransition: boolean | { types }`; per-navigation `viewTransition` (default false). `types`: string array or `(info: { fromLocation?, toLocation, pathChanged, hrefChanged, hashChanged }) => string[] | false` (`false` skips the transition). Falls back to plain `startViewTransition` when types unsupported; ignored when API unsupported. Source: `R:api/router/ViewTransitionOptionsType.md`, `R:api/router/NavigateOptionsType.md`
- **Route-level code splitting**: **Supported.** Critical config (path parsing, search validation, `loader`, `beforeLoad`, context, static data, links/scripts/styles) stays in the main route chunk; non-critical (`component`, `errorComponent`, `pendingComponent`, `notFoundComponent`) is lazy. **Automatic** (`autoCodeSplitting`, Vite/Rspack/Rsbuild/Webpack): compiler rewrites route files into a reference file + virtual `?tsr-split=` modules. Default groupings `[['component'], ['errorComponent'], ['notFoundComponent']]`; `loader` not split by default (splitting it adds a round-trip; "highly discouraged"). Customization precedence: per-route `codeSplitGroupings` > plugin `splitBehavior({ routeId })` > plugin `defaultBehavior`. Rule: **don't export** route properties (exported ones aren't split). Manual: `*.lazy.tsx` + `createLazyFileRoute`, code-based `createLazyRoute` + `route.lazy(() => import(...))`, `lazyRouteComponent(importer, exportName = 'default')`. `getRouteApi('/path')` gives typed hooks (`useLoaderData`, `useLoaderDeps`, `useMatch`, `useParams`, `useRouteContext`, `useSearch`) in split files without importing the route. Start docs say file-based routing "ensure[s] proper code-splitting" but don't state the `autoCodeSplitting` default for Start (from memory: on by default in Start, unverified). Source: `R:guide/automatic-code-splitting.md`, `R:guide/code-splitting.md`, `S:guide/routing.md`
- **Base path**: **Supported.** Router `basepath` (default `/`); implemented internally as a URL rewrite and composed with any custom `rewrite` (basepath stripped first on input, added last on output). Asset base is the bundler's (`base` in Vite; docs recommend `base: ''` with CDN `transformAssets`). Server-function endpoint base defaults to `/_serverFn` ("if you have configured your server function base path..." — config key not documented). Source: `R:api/router/RouterOptionsType.md`, `R:guide/url-rewrites.md`, `S:guide/spa-mode.md`, `S:guide/cdn-asset-urls.md`

  - **Bidirectional URL rewrites**: router `rewrite: { input({ url }), output({ url }) }` (return mutated URL, new URL, href string, or `undefined`); `composeRewrites([...])` (inputs in order, outputs reversed); `location.publicHref` vs `location.href`; applied on server request parsing too; cross-origin output triggers full page load automatically. Use cases: locale prefixes, subdomain→path, legacy URLs, multi-tenant. `R:guide/url-rewrites.md`

  - History types: `createBrowserHistory` (default), `createHashHistory`, `createMemoryHistory`, `createServerHistory` (fixed URL, no-op navigation, used by SSR handlers). `R:guide/history-types.md`
  - `staticData` per route (sync object, readable on `match.staticData`; enforce/opt via `StaticDataRouteOption` declaration merging). `R:guide/static-route-data.md`
  - Router events `router.subscribe(event, fn)`: `onBeforeNavigate` → `onBeforeLoad` → `onLoad` → `onBeforeRouteMount` → `onResolved` → `onRendered`; payload `{ fromLocation?, toLocation, pathChanged, hrefChanged, hashChanged }`. `R:guide/router-events.md`

## 2. Rendering modes

- **SSR**: **Supported, default on.** Initial request: all matched routes' `beforeLoad` + `loader` run on the server, components render, HTML + dehydrated data are sent, client hydrates. Full-document SSR: root route renders `<html>`, `<head><HeadContent/></head>`, `<body>...<Scripts/></body>` (`<Scripts/>` is required — emits route scripts and marks where streamed hydration data is inserted; without it the page cannot hydrate). A new router is created per request via `getRouter()`; server history holds only the request URL. Loader data and `beforeLoad` context are dehydrated/rehydrated automatically. Source: `S:guide/routing.md`, `S:guide/selective-ssr.md`, `R:guide/ssr.md`
- **Streaming SSR**: **Supported, default.** The built-in server entry is `createStartHandler(defaultStreamHandler)`. Mechanism: React Suspense + **unawaited promises in loader return values** (automatic deferral; `defer()` no longer needed). Server tracks returned promises, renders up to Suspense boundaries, then streams each resolved value (or serialized error) via inline `<script>` plus the resolved boundary HTML; client placeholders resolve and render or throw to the nearest error boundary. Consume with `<Await promise={p}>{(v) => ...}</Await>` (React 18; suspends; rejects → error boundary) or React 19 `use()`. Deferred promises share the loader's cache lifecycle and can be preloaded. Non-streaming alternatives exist in Router (`defaultRenderHandler`, `renderRouterToString` — sync string render that emits Suspense fallbacks without waiting). Once the entry has returned its `Response`, errors in the streamed body cannot change status/headers. Custom render pipeline via `defineHandlerCallback((ctx) => defaultStreamHandler(ctx))`. Source: `R:guide/deferred-data-loading.md`, `R:guide/ssr.md`, `R:api/router/awaitComponent.md`, `R:api/router/deferFunction.md`, `S:guide/server-entry-point.md`
- **Static pre-rendering incl. dynamic params**: **Supported.** `tanstackStart({ prerender: {...}, pages: [...] })`. Runs the SSR build at build time (loaders execute then).

  | Option | Default (as stated) | Behavior |
  |---|---|---|
  | `prerender.enabled` | `false` (example comment "Switch to true") | Turn on prerendering |
  | `autoSubfolderIndex` | `true` | `/page/index.html` vs `/page.html` |
  | `autoStaticPathsDiscovery` | `true` | Discover all static routes and merge with `pages`; if disabled only `/` + `pages` |
  | `concurrency` | example `14` | Parallel prerender jobs |
  | `crawlLinks` | `true` | Extract `<a>` links from rendered HTML and prerender them too |
  | `filter` | — | `({ path }) => boolean` |
  | `retryCount` / `retryDelay` | example `2` / `1000` ms | Retries for failed pages |
  | `maxRedirects` | example `5` | Redirects followed during prerender |
  | `failOnError` | example `true` | Fail build on error |
  | `onSuccess` | — | `({ page }) => void` |
  | `pages[]` | — | `{ path, prerender: { enabled, outputPath, ... } }` per-page overrides |

  Auto-discovery **excludes** routes with path params, pathless `_` layouts, and component-less (API) routes. Dynamic-param pages are prerendered only if **reachable by crawling** or **listed in `pages`** — there is no `generateStaticParams`-style hook (lists must be computed in config). The ISR guide uses a `prerender.routes: ['/blog', '/blog/posts/*']` key that the prerender guide doesn't document (inconsistency). Build-time data caching for client navigation: **Static Server Functions** (experimental, see §5). Source: `S:guide/static-prerendering.md`, `S:guide/isr.md`
- **Client-only / SPA routes and full SPA mode**: **Supported.** Per route: `ssr: false` (see per-route control). Full SPA mode: `tanstackStart({ spa: { enabled: true, maskPath: '/', prerender: {...} } })`. Build adds a prerender step that renders **only the root route** with the router's pending fallback in place of matched routes, written to `/_shell.html` (spa.prerender defaults: `outputPath: '/_shell.html'`, `crawlLinks: false`, `retryCount: 0`; accepts all prerender options). Root-route `loader`/server code runs at build and is baked into the shell. `router.isShell()` true while rendering the shell (flips false right after hydration → potential FOUC). Hosts must: serve existing static files, allow-list `/_serverFn/*` and server-route prefixes (e.g. `/api/*`) to the server, and rewrite all other 404s to the shell (`/* /_shell.html 200`). Server functions/routes still work if a server is deployed. Other routes can additionally be prerendered. Source: `S:guide/spa-mode.md`
- **Partial hydration (islands / server components / equivalent)**: **Partial — two experimental mechanisms.**
  1. **React Server Components (experimental, opt-in)**: enable with `tanstackStart({ rsc: { enabled: true } })` + `@vitejs/plugin-rsc` (Vite) or built into Rsbuild; React 19+, Vite 8+/Rsbuild 2+. Model is **client-led composition**: RSC output is produced inside **server functions** and returned through loaders — not "server components by default". APIs (`@tanstack/react-start/rsc`): `renderServerComponent(<El/>)` → inline renderable (no slots); `createCompositeComponent((props) => <El/>)` → rendered with `<CompositeComponent src={...} {...slots}/>`; slot kinds: `children` (server can't pass data), render props (server passes serializable args), component props. Slots are opaque proxies on server (`Children.map`/`cloneElement` don't work); slot args must be Flight-serializable. Cached by router cache (key = path + params + `loaderDeps`), `router.invalidate()` refetches; with TanStack Query set `structuralSharing: false`. Combine with `ssr: 'data-only'` / `false`. Patterns: parallel `Promise.all`, bundled multiple components, deferred component promises + `use()` + Suspense, Suspense inside RSC, **async-generator streaming of components**. `React.cache` works for request-scoped memoization; `Link` works inside RSC; CSS Modules/global CSS extracted. Uses React Flight (Start's custom serialization not yet available in RSC). Low-level: `renderToReadableStream` (server functions only), `createFromFetch`, `createFromReadableStream`. ESLint rules `no-async-client-component`, `no-client-code-in-server-component`. Source: `S:guide/server-components.md`, `docs/start/eslint/*`
  2. **Deferred hydration `<Hydrate>` (experimental)**: gates inside the single React tree (explicitly *not* Astro islands: "Astro composes runtimes, Start schedules one"); server HTML preserved until a strategy fires; compiler moves children to a separate chunk by default. Details under hydration strategies.
- **Static shell with dynamic holes (PPR-like)**: **Not supported** as a build-time-shell + request-time-holes model. Nearest: SPA shell (whole app client-rendered under a prerendered root), selective SSR server fallbacks (`pendingComponent` rendered server-side for the first non-SSR route), streaming SSR with deferred promises. Not found in docs: any mechanism to prerender a page and fill dynamic regions per request.
- **Per-route rendering-mode control**: **Supported (Selective SSR).** Route option `ssr`:

  | Value | Server `beforeLoad`/`loader` | Server component render | Notes |
  |---|---|---|---|
  | `true` (default) | yes; context + loader data sent to client | yes | Client navigations run them in browser |
  | `'data-only'` | yes | no (client renders) | — |
  | `false` | no (run on client during hydration) | no | — |
  | `({ params, search }) => true \| false \| 'data-only' \| undefined` | per result | per result | Runs **only on the server on the initial request**, stripped from client bundle; `params`/`search` arrive as `{ status: 'success', value } \| { status: 'error', error }` after validation |

  Default changeable via `createStart(() => ({ defaultSsr: false }))` in `src/start.ts` (an example comment also says "`defaultSsr: false` on the router" — ambiguous). **Inheritance**: children inherit the parent's value and can only become more restrictive (`true` → `'data-only'` → `false`); a child `ssr: true` under `false` has no effect. **Fallback**: for the first route with `false`/`'data-only'`, the server renders its `pendingComponent` (or `defaultPendingComponent`, else nothing); on the client the fallback shows at least `pendingMinMs`/`defaultPendingMinMs` even without loaders. Root route with `ssr: false` still needs `shellComponent` (always SSR'd `<html>` wrapping root component/error/notFound). Component-level: `<ClientOnly fallback>` (renders fallback on server + first client render), `useHydrated()` (false during SSR and first client render, true afterwards), `createClientOnlyFn`. Source: `S:guide/selective-ssr.md`, `S:guide/execution-model.md`, `R:api/router/clientOnlyComponent.md`
- **Hydration strategies**: **Supported.** Default: full-document hydration `hydrateRoot(document, <StartClient/>)` from optional `src/client.tsx` (auto-generated if absent; can wrap with error boundaries/StrictMode). **Deferred hydration (experimental)** `<Hydrate>` from `@tanstack/react-start`, strategies from `@tanstack/react-start/hydration`:

  | `Hydrate` prop | Type / default | Behavior |
  |---|---|---|
  | `when` (required) | strategy \| `() => strategy` | When boundary hydrates; function form evaluated client-only, must return synchronously |
  | `split` | `true` | Compiler extracts children to a child chunk; literal `split={false}` only defers hydration work |
  | `prefetch` | strategy \| `async (ctx) => ...` | Start loading chunk/data early without changing `when`; strategy form invalid with `split={false}`; procedural ctx `{ preload(), waitFor(strategy) → 'prefetch'|'hydrate'|'abort', signal, element }`; awaited work blocks hydration if `when` fires first |
  | `fallback` | ReactNode | Only for boundaries that first mount **after** app hydration (client nav) and suspend; never replaces initial server HTML; stripped from server bundle when statically visible |
  | `onHydrated` | `() => void` | Fires once after hydration |

  | Strategy | Options / default | Behavior |
  |---|---|---|
  | `load()` | — | Hydrate with app |
  | `idle()` | `{ timeout }` default 2000 | `requestIdleCallback` |
  | `visible()` | `{ rootMargin = '600px', threshold }` | IntersectionObserver on marker |
  | `media(query)` | — | When media query matches |
  | `interaction()` | `{ events }`; default `pointerenter, focusin, pointerdown, click` (15 supported events) | Hydrates on intent; can hydrate unresolved ancestor chain and **re-dispatch** a same-type event (payload details not guaranteed) |
  | `condition(bool \| fn)` | — | Hydrate once truthy; stays hydrated |
  | `never()` | — | Initial SSR HTML stays static; not usable as prefetch; mounts normally on later client nav |

  Edge cases: nested boundaries hydrate parent-first; React may hydrate a gated boundary early if outside state/props/context updates require reconciliation (except `never()`); split chunks are **not** modulepreloaded with the route; CSS of deferred boundaries is still linked in SSR HTML; extraction rejects function-as-children, hooks directly in extracted JSX, `this`/`super` captures, and aliasing `Hydrate` to a variable (import renames OK); inline callbacks need no `useCallback`; change `key` to reset a boundary. `HydrateOptions` type for reusable prop objects. Hydration-mismatch guidance: deterministic locale/time zone via cookie/`Accept-Language` middleware, `<ClientOnly>`, `useHydrated`, `ssr: 'data-only'|false`, `suppressHydrationWarning`. Source: `S:guide/deferred-hydration.md`, `S:guide/client-entry-point.md`, `S:guide/hydration-errors.md`
- **Notable extras**: `ScriptOnce` (inline script executed before hydration, removes itself, not re-rendered on client nav — theme flash prevention) `R:guide/document-head-management.md`; Early Hints and CSS inlining (see §10); `Wrap`/`InnerWrap` must not render DOM; RSC + selective SSR combos; Solid's deferred hydration replaces server DOM with a fresh mount when the gate opens (`SS:guide/deferred-hydration.md`).

## 3. Data loading

- **Where data is fetched**: Route **`loader`** (isomorphic — runs on the server for the initial SSR request and **in the browser on client navigation**; not server-only), **`beforeLoad`** (runs before loaders; returns context; auth/redirect checks), **server functions** (`createServerFn`, callable from loaders/components/other server functions; the only way to guarantee server execution of privileged reads from a loader), **RSC** via server functions (experimental), external caches (TanStack Query via `@tanstack/react-router-ssr-query`). Docs warn: secrets/`process.env` in a loader leak to the client; move privileged reads into server functions. Source: `S:guide/execution-model.md`, `S:migrate-from-next-js.md`, `R:guide/data-loading.md`, `S:guide/tanstack-query.md`
- **Loader execution model**: **Lifecycle per URL change**: (1) matching top-down: `params.parse`, `validateSearch`; (2) **serial** `beforeLoad` parent→child (+`onError` → errorComponent); (3) **parallel** `component.preload` + `loader` for all matched routes; pendingComponent after `pendingMs`; component. If `beforeLoad` fails, that route's loader and descendants don't run. Children can opt into waiting on a parent via `parentMatchPromise`. `beforeLoad` return objects are merged into context for loader and children. No separate server/client loader pair: the same `loader` runs on whichever side handles the request; `ssr: false` moves it to the client during hydration; `ssr: 'data-only'` keeps it on the server for initial load.

  **`loader` / `beforeLoad` arguments** (`R:api/router/RouteOptionsType.md`, `R:guide/data-loading.md`):

  | Arg | loader | beforeLoad | Meaning |
  |---|---|---|---|
  | `params` | ✓ | ✓ | All parsed path params (incl. parents) |
  | `search` | ✗ | ✓ | Full validated search (loader must use `deps`) |
  | `deps` | ✓ | — | Return of `loaderDeps` (or `{}`) |
  | `context` | ✓ (parent + own beforeLoad) | ✓ (parent) | Router context chain |
  | `location` | ✓ | ✓ | `ParsedLocation` |
  | `cause` | ✓ | ✓ | `'enter'` \| `'stay'` \| `'preload'` |
  | `preload` | ✓ | ✓ | true for speculative preload |
  | `abortController` | ✓ | ✓ | Shared across joined preload/navigation consumers; aborted only when no consumer needs the work |
  | `parentMatchPromise` | ✓ | — | `Promise<RouteMatch>` of parent (undefined at root) |
  | `route` | ✓ | — | Route object |
  | `buildLocation` | — | ✓ | Build typed locations |
  | `navigate` | deprecated | deprecated | Use `throw redirect()` |

  Loader object form: `loader: { handler, staleReloadMode: 'background' | 'blocking' }`. Return/throw `redirect()` or `notFound()` from either. Source: `R:guide/data-loading.md`, `R:api/router/RouteOptionsType.md`
- **Request deduplication**: **Partial.** In-flight loader work for the same match (path + params + `loaderDeps`) is **shared between preloads and navigations** ("join a loader that is still in flight"); `router.invalidate` selection applies to all generations of a match ID. Not deduped across different routes ("No shared caching/deduping between routes" listed as a router-cache con). No automatic dedupe of server-function calls or `fetch` documented; RSC can use `React.cache` (request-scoped). Source: `R:guide/data-loading.md`, `R:guide/preloading.md`, `S:guide/server-components.md`
- **Passing server data to client components**: **Supported, automatic.** Loader return values and `beforeLoad` context are serialized into the HTML and rehydrated (`R:guide/ssr.md` lists `undefined`, `Date`, `Error`, `FormData` beyond JSON; Start server functions type-check serializability with `strict`; `Response` allowed as a server-fn return). Read with `Route.useLoaderData()`, `useLoaderData({ from, strict = true, select, structuralSharing })`, `getRouteApi(id).useLoaderData()`, `Route.useRouteContext()`. Server→client middleware context via `sendContext`. RSC payloads use React Flight (primitives, Dates, React elements). Router `dehydrate`/`hydrate` options for custom extra state. Source: `R:api/router/useLoaderDataHook.md`, `S:guide/server-functions.md`, `S:guide/middleware.md`, `R:api/router/RouterOptionsType.md`
- **Client-side data cache**: **Supported — built-in SWR router cache**, keyed by fully parsed pathname (params) + `loaderDeps` (deep equality).

  | Option (route / router default) | Default | Behavior |
  |---|---|---|
  | `staleTime` / `defaultStaleTime` | `0` | Navigation data immediately stale; re-entering same key or `router.load()` revalidates **in background** while showing cached data; `Infinity` disables stale reloads |
  | `preloadStaleTime` / `defaultPreloadStaleTime` | `30_000` | Freshness of preload-produced data (first navigation can reuse) |
  | `gcTime` / `defaultGcTime` | 5 min | Retention of unused navigation data (pruned at later reconciliation) |
  | `preloadGcTime` / `defaultPreloadGcTime` | 5 min | Retention of unused preload data |
  | `loader.staleReloadMode` / `defaultStaleReloadMode` | `'background'` | `'blocking'` waits for stale reload before navigation resolves |
  | `shouldReload` | undefined | `boolean \| (loaderArgs) => boolean`; `false` never reloads on subsequent matches, `true` always, `undefined` = SWR rules (Remix `shouldRevalidate`-like; combine with `gcTime: 0` to opt out of caching) |
  | `loaderDeps` | — | Changed deps force reload regardless of staleTime; must be deterministic; return only used keys |
  | `preload` (route) | `true` | `false` skips loader during preloads only |

  Cons stated by docs: no persistence, no cross-route sharing, no mutation APIs, coarse invalidation. TanStack Query integration recommended for richer needs (one QueryClient **per router/request**, created in `getRouter`; `defaultPreloadStaleTime: 0`; integration handles dehydrate/hydrate/streaming; `wrapQueryClient: false` if you own the provider). Source: `R:guide/data-loading.md`, `S:guide/tanstack-query.md`, `R:guide/external-data-loading.md`
- **Deferred / streamed data**: **Supported.** Unawaited promises in loader return (see §2); `<Await>`/`use()`; streamed results/errors via inline scripts; promises share loader cache lifecycle and preload. Server functions can stream typed `ReadableStream<T>` or **async generators** (`async function*` handler; client `for await (const chunk of await fn())`, chunks typed). RSC deferred component promises and async-generator component streams. Source: `R:guide/deferred-data-loading.md`, `S:guide/streaming-data-from-server-functions.md`, `S:guide/server-components.md`
- **Dependency tracking & invalidation**: **Supported (manual, coarse/filterable).** Implicit deps: path params; explicit: `loaderDeps`. `router.invalidate({ filter?, sync?, forcePending? })`: invalidates committed, cached and in-flight generations (filter selects by match; all generations with the same match ID), retires matching preload lanes, **re-runs `beforeLoad`**, marks loader data stale and reloads active matches via normal protocol (background by default; `sync: true` awaits; `forcePending: true` shows pending UI even with data); inactive cached data reloads on reuse; route `context` reused while match ID unchanged. `router.clearCache({ filter? })` removes cached matches/preload lanes (not current matches). `router.load({ sync })`. No tag/path-based server invalidation. Source: `R:api/router/RouterType.md`, `R:guide/data-mutations.md`
- **Access to request context**: **Partial in loaders (isomorphic), full in server code.** Loaders don't receive the `Request`; use router **context** (`createRootRouteWithContext<T>()` + `createRouter({ context })`; extended by `beforeLoad`; default `{}`; dependency injection of clients/hooks) or call a server function that uses `getRequest()`, `getRequestHeader()`, `getCookie()` (`@tanstack/react-start/server`). Server-side **request context**: values passed as `handler.fetch(request, { context })` in a custom `src/server.ts`, typed via `Register { server: { requestContext } }`, available to global/request/function middleware, server routes, server functions "and the router itself". Source: `R:guide/router-context.md`, `S:guide/server-entry-point.md`, `S:guide/server-functions.md`
- **Notable extras**: pending defaults (`pendingMs` 1000, `pendingMinMs` 500); `useLoaderDeps`; `wrapInSuspense`; `getRouteApi`; RSC cache key semantics; Query integration guidance for avoiding duplicate post-hydration reads; `staticData`; ESLint ordering rule for inference.

## 4. Mutations

- **Form handling without JS (progressive enhancement)**: **Partial / minimal.** No `<Form>` component or route actions (Router comparison: "`<Form>` API 🛑"; Start comparison: "Server functions can be called from event handlers; use a form library when needed"). Server functions expose a **`.url` property** usable as an HTML form `action` — documented in a single sentence with no further detail. Next.js migration guide: event-handler forms "require JavaScript and keep their fields disabled until hydration"; for PE "use a FormData-compatible server function URL or an ordinary form POST to a server route" with your own validation/CSRF/redirect; "Do not treat `createServerFn` as a drop-in replacement for the React form Action protocol". Plain `<form action="/search" method="get">` + search params is the documented PE pattern. Source: `S:guide/server-functions.md`, `S:migrate-from-next-js.md`, `S:comparison.md`, `R:comparison.md`, `S:guide/execution-model.md`
- **Server functions / RPC / actions**: **Supported (core feature).** `createServerFn(opts?)` from `@tanstack/react-start`:

  | Option / builder | Values / default | Behavior |
  |---|---|---|
  | `method` | `'GET'` (default) \| `'POST'` | HTTP method of RPC (GET results cacheable via headers; FormData only for POST) |
  | `strict` | `true` \| `false` \| `{ input?: false, output?: false }` | Type-level serializability checks of validator input and handler output (runtime unaffected) |
  | `.middleware([...])` | function or request middleware | Runs before handler (see §6) |
  | `.validator(fn \| schema)` | function, Zod/Standard-Schema-like | Validates/transforms `data`; throws → call rejects (`.inputValidator` removed in 1.169) |
  | `.handler(async ({ data, context }) => ...)` | | Server-only body; may return values, `Response`, ReadableStream, async generator, RSC; may throw `redirect()`/`notFound()`/errors |
  | Call: `fn({ data, headers, fetch })` | | `headers` merge after middleware headers; `fetch` overrides custom fetch |

  Compilation: client bundle gets an RPC stub (fetch to server); **during SSR server functions are called directly** (no HTTP). Static imports are safe anywhere; **dynamic `import()` of server-function modules can break bundling**. IDs: SHA-256 hash of a seed (no file paths leaked), collisions suffixed `_1`, `_2`; customizable via plugin `serverFns.generateFunctionId({ filename, functionName })` (**experimental**). Suggested file split: `*.functions.ts` (wrappers), `*.server.ts` (server-only helpers), plain shared files. `useServerFn(fn)` hook returns a callable (not `{data,isLoading}`) and makes thrown redirects/notFound work from components. Server functions are **same-origin** endpoints; public/cross-origin APIs should be server routes. Every server function is independently callable, so auth must be enforced in the function (middleware), not just route `beforeLoad`. Source: `S:guide/server-functions.md`, `S:guide/authentication.md`, `S:guide/import-protection.md`
- **Pending, error and validation-error state**: **Not built in.** No submission/pending state API; track in component state or use TanStack Query `useMutation` (`isPending`, `isError`). Errors: a call **rejects with whatever was thrown** (including a thrown `Response` or falsy values; return a `Response` to resolve with it); thrown errors are serialized to the client with message; errors thrown by request middleware during a server-fn call reach the client with their message and status (no longer always 500). No structured field-level validation-error format. Source: `S:migrate-from-release-candidate.md`, `S:guide/server-functions.md`, `S:guide/tanstack-query.md`, `S:guide/authentication.md`
- **Optimistic UI**: **Not built in.** Router "does not manage mutation or submission state" and has "no built-in cache-level optimistic update APIs"; recommends TanStack Query/SWR/etc. (`setQueryData` with cancellation/rollback). `useMatchRoute({ pending: true })`/`<MatchRoute pending>` give optimistic navigation indicators. (Router comparison table nonetheless claims "Optimistic UI ✅".) Source: `R:guide/data-mutations.md`, `R:guide/data-loading.md`, `S:guide/tanstack-query.md`
- **Data refresh after a mutation**: **Manual.** Call `await router.invalidate()` (background SWR by default; `{ sync: true }` waits for loaders; re-runs `beforeLoad`, so auth context refreshes) and/or `queryClient.invalidateQueries`. Docs stress these don't purge CDN or DB caches. Router data-mutations guide recommends clearing mutation state on route change (mutation keys). No automatic revalidation. Source: `R:guide/data-mutations.md`, `S:migrate-from-next-js.md`, `S:guide/tanstack-query.md`
- **Redirects after mutation**: **Supported.** `throw redirect({ to | href, params, search, statusCode, headers, replace, resetScroll, ... })` inside a server function; handled automatically when called from route lifecycles or via `useServerFn`. Serialized server-function replies **never carry `Location`/`Content-Encoding`/`Content-Length` from response helpers and ignore helper 204/205/304**; a returned `Response` with a redirect status is followed by the browser before the caller sees it — so use `redirect()`. Or `navigate()` after `await`. Source: `S:guide/server-functions.md`, `S:migrate-from-release-candidate.md`, `R:api/router/RedirectType.md`
- **File uploads**: **Partial.** `FormData` is an accepted input for POST server functions (validator receives `FormData`, must check `instanceof FormData`); server routes can read `request.formData()`. Not found: size limits, streaming upload helpers, multipart parsing options. Source: `S:guide/server-functions.md`, `S:guide/server-routes.md`
- **Multiple actions per page**: **Supported** implicitly — any number of server functions, each with its own ID/URL; no per-route action concept. Source: `S:guide/server-functions.md`
- **CSRF protection built in**: **Supported (for server functions, with caveats).** `createCsrfMiddleware({ filter?, origin?, allowRequestsWithoutOriginCheck? })` verifies `Sec-Fetch-Site`, `Origin`, or `Referer` is same-origin; **requests with none of these headers are rejected** unless `allowRequestsWithoutOriginCheck: true`; `origin` overrides the compared public origin. **Auto-installed for server functions only when the app has no `src/start.ts`**; with a custom `src/start.ts` you must add it to `requestMiddleware` (recommended `filter: (ctx) => ctx.handlerType === 'serverFn'`), else a dev warning (silence with plugin `serverFns.disableCsrfMiddlewareWarning: true`). Without a filter it validates every request it handles; can be attached to server routes (`server.middleware: [createCsrfMiddleware()]`). Server routes/plain form posts are **not** protected by default. Source: `S:guide/server-functions.md`, `S:guide/middleware.md`, `S:guide/authentication-server-primitives.md`
- **Notable extras**: client-side function middleware can add headers / custom fetch / `sendContext`; header precedence (earlier mw < later mw < call site); fetch precedence (call site > later mw > earlier mw > `createStart({ serverFns: { fetch } })` > global fetch; custom fetch is client-only, SSR calls direct); server function streaming; RSC returned from mutations; `AbortSignal` cancellation mentioned without API detail.

## 5. Caching & revalidation

- **Page/HTML caching**: **Partial — HTTP headers only.** No framework HTML cache store. Set headers per page with route `headers: ({ matches, match, params, loaderData }) => Record<string,string>` (applied during SSR), via `setResponseHeader(s)` in server functions/middleware, or by mutating `result.response.headers` after `await next()` in request middleware. Prerendered pages are files. Docs warn: `public` on identity-dependent responses causes cross-tenant leaks; use `private`/`no-store` + `Vary`. Source: `S:guide/isr.md`, `S:guide/server-functions.md`, `S:guide/production-checklist.md`, `R:api/router/RouteOptionsType.md`
- **Time-based revalidation (ISR)**: **Partial — delegated to CDN.** "ISR" = prerender at build + `Cache-Control: public, max-age, s-maxage, stale-while-revalidate` honored by the CDN; regeneration = CDN re-requesting the origin SSR. Examples for Cloudflare (`CDN-Cache-Control`), Netlify (`_headers` file), Vercel (`s-maxage`). Docs caution behavior differs by host ("A `Cache-Control` header alone does not guarantee the same regeneration, invalidation, or shared-cache behavior on every host"). No framework-managed regeneration or `revalidate` export. Source: `S:guide/isr.md`, `S:start-vs-nextjs.md`, `S:comparison.md`
- **On-demand revalidation (by path, by tag)**: **Not supported** natively. Doc pattern: a secret-protected POST server route that calls your CDN's purge API. No `revalidatePath`/`revalidateTag`. Source: `S:guide/isr.md`, `S:migrate-from-next-js.md`
- **Data-level / function-level caching**: **Partial.** No server-side data cache API (`use cache`/`unstable_cache` equivalent not found). **Static Server Functions (experimental)**: add `staticFunctionMiddleware` (from `@tanstack/start-static-server-functions`, must be the **last** middleware) to a GET server function; during prerender its result is written as a static JSON file keyed by function ID + payload hash, embedded in prerendered HTML, hydrated, and later client calls fetch the static JSON. RSC `React.cache` request-scoped. Router loader cache client-side. Source: `S:guide/static-server-functions.md`, `S:guide/server-components.md`
- **Client navigation cache**: **Supported** — router SWR cache (§3) + preload cache (30s fresh / 5 min retained); RSC loader results cached the same way. Source: `R:guide/data-loading.md`, `R:guide/preloading.md`
- **HTTP cache-header helpers**: **Partial** — generic header setters only (`headers` route option, `setResponseHeader`, `setResponseHeaders`, `appendResponseHeader`, `setResponseStatus`); ETag example via middleware hashing `result.data`; no typed `cacheControl()` helper. Source: `S:guide/isr.md`, `S:guide/server-functions.md`
- **Preview / draft mode bypass**: **Not found in docs.**
- **Notable extras**: `transformAssets` manifest cache (`cache: true` default, `warmup`); `router.clearCache`; docs' explicit taxonomy of caches (browser data, router loaders, Query, server data, generated pages, CDN) and the statement that `router.invalidate()` "does not purge a CDN, clear a database cache, or revalidate all statically generated pages" (`S:migrate-from-next-js.md`).

## 6. Server & API

- **API routes / endpoints (per HTTP method)**: **Supported — "server routes"** in the same `src/routes` tree via a `server` property on `createFileRoute`:
  - `server.handlers`: object `{ GET, POST, PUT, PATCH, DELETE, ... : ({ request, params, context }) => Response | Promise<Response> }`, or function `({ createHandlers }) => createHandlers({ GET: { middleware: [...], handler }, POST: fn })` for per-method middleware.
  - `server.middleware`: route-level middleware for all handlers (runs before handler-specific middleware).
  - Same file may also define `component` (app route) — one file serves page + endpoint methods.
  - Conventions mirror routing: `users.ts`, `users/$id.ts`, splat `file/$.ts` (`params._splat`), escaped `my-script[.]js.ts`, `users[.]json.ts`. Only one handler file per resolved path (`users.ts` + `users.index.ts` + `users/index.ts` conflict → error).
  - Responses: raw `Response`, `Response.json()`, status/headers via `Response` init or helpers. `HEAD` / 204 / 205 / 304 strip bodies in error conversion. Behavior for undefined methods (405?) **not documented**.
  - Pathless layouts add middleware to groups; break-out routes escape parent middleware.
  - Note: the RSC low-level example imports `createAPIFileRoute` from `@tanstack/react-start/api`, which conflicts with the documented `server.handlers` API (likely stale).
  Source: `S:guide/server-routes.md`, `S:guide/server-entry-point.md`, `S:guide/server-components.md`
- **Middleware (global, per-route, ordering, capabilities)**: **Supported — two kinds.**

  | | Request middleware `createMiddleware()` / `{ type: 'request' }` | Function middleware `createMiddleware({ type: 'function' })` |
  |---|---|---|
  | Scope | Every server request through it: SSR, server routes, server functions | Server functions only |
  | Methods | `.middleware([...])`, `.server(fn)` | `.middleware([...])`, `.validator()`, `.client(fn)`, `.server(fn)` (order enforced by types) |
  | `.server` args | `{ next, context, request }` | `{ next, context, data, ... }` |
  | Deps | Request mw only | Request + function mw |

  `next(opts?)` must be called to continue; can short-circuit, read the downstream result (`result.response` mutable), and pass `{ context }` (merged for downstream), `{ sendContext }` (client→server: serialized and sent, **must be validated server-side**; server→client: returned from `next()` in `.client`, typed only for mw known in the chain), `{ headers }` and `{ fetch }` (client side). Client context isn't sent unless `sendContext` is used; when none sent, `sendContext` is `undefined`. **Global**: `src/start.ts` → `export const startInstance = createStart(() => ({ requestMiddleware: [...], functionMiddleware: [...], defaultSsr, serverFns: { fetch } }))` (file not in default template). **Ordering**: dependency-first; global request mw → global function mw → per-function mw chain (deps before dependents) → handler; route-level `server.middleware` before handler-specific. **Per-route**: server-route `server.middleware`/per-method middleware; server-fn `.middleware()`. Whether a page route's `server.middleware` wraps its SSR render is not stated. **Tree-shaking**: `.server` bodies and validators removed from client bundles. **Factories**: functions returning middleware (e.g. `authorizationMiddleware({ client: ['read'] })`). Request errors: thrown errors become Start's error response (helpers' status/headers preserved). Source: `S:guide/middleware.md`, `S:migrate-from-release-candidate.md`
- **Request context (cookies, headers, locals)**: **Supported.** `@tanstack/react-start/server` helpers (usable in server functions, middleware, server routes): `getRequest()`, `getRequestHeader(name)` (`''` for present-empty, `undefined` if missing), `getCookie`, `setCookie(name, value, { httpOnly, secure, sameSite, path, maxAge, ... })`, `deleteCookie`, `setResponseHeader` (**`set-cookie` via this replaces all outgoing cookies**), `setResponseHeaders(Headers)`, `appendResponseHeader`, `setResponseStatus(code, text?)` (ignores codes outside 200–599 with dev warning). Response helpers **override** the status/headers of a returned/thrown `Response`. "Locals": middleware `context` + typed server `requestContext` from the server entry. Importing `@tanstack/react-start/server` in client code is denied by import protection. Invalid percent-encoded paths get `400` before middleware runs. Source: `S:guide/server-functions.md`, `S:migrate-from-release-candidate.md`, `S:guide/authentication-server-primitives.md`, `S:guide/server-entry-point.md`
- **Streaming responses and SSE**: **Partial.** Server routes return any Web `Response` (stream bodies possible by platform); server functions stream typed `ReadableStream` / async generators; RSC Flight streams. **SSE not explicitly documented.** Source: `S:guide/streaming-data-from-server-functions.md`, `S:guide/server-routes.md`
- **Running work after the response (waitUntil/after)**: **Not found in docs.** (Cloudflare custom entries can add queues/scheduled/Durable Objects per Cloudflare's docs.) Source: `S:guide/server-entry-point.md`
- **Server-only code boundaries**: **Supported, extensive.** (a) **Import protection** (enabled by default, in dev and build): client env denies `**/*.server.*` files and the `@tanstack/react-start/server` specifier; server env denies `**/*.client.*`; `node_modules` excluded; marker imports `import '@tanstack/react-start/server-only'` / `'.../client-only'` (both in one file = error); type-only imports ignored. Behavior: `{ dev: 'mock', build: 'error' }` — dev replaces violating imports with a recursive Proxy mock + warning; build checks **after tree-shaking** (dev may show false positives). Options: `enabled` (true), `behavior`, `log` (`'once'`), `include` (srcDirectory), `exclude`, `ignoreImporters`, `maxTraceDepth` (20), `client.{specifiers (additive), files, excludeFiles}`, `server.{specifiers (replaces), files, excludeFiles}`, `onViolation(info)` (can override verdict). Violation output: full import trace with `file:line:col`, code frame, suggestions. (b) **Environment functions**: `createServerOnlyFn(fn)` (client stub throws), `createClientOnlyFn(fn)` (server stub throws), `createIsomorphicFn().server(fn).client(fn)` (missing side = no-op returning `undefined`); compiler prunes imports only referenced inside removed implementations. (c) Env vars: server reads any `process.env` **per request** (module-scope reads are undefined on Workers and may inline into client); client sees only `VITE_` (Vite) / `PUBLIC_` (Rsbuild) prefixed. (d) ESLint plugin start (RSC boundaries). Mixed barrels flagged. Source: `S:guide/import-protection.md`, `S:guide/environment-functions.md`, `S:guide/execution-model.md`, `S:guide/environment-variables.md`
- **Notable extras**:
  - **Server entry** `src/server.ts` (auto-detected; else built-in; other path via plugin `server.entry`, relative to `srcDirectory` default `src`): `export default createServerEntry({ fetch(request, opts) })`; `handler.fetch(request, { context, onEarlyHints, responseLinkHeader })`; `createStartHandler(cb | { handler, transformAssets })`, `defaultStreamHandler`, `defineHandlerCallback`, `handleStartError(error)`. Raw `createStartHandler` handlers **rethrow** the original error (since 1.169); `createServerEntry` converts uncaught errors. Source: `S:guide/server-entry-point.md`
  - **Error-response rules**: generic JSON body (no message/stack) with status 500 unless an error status (400–599) comes from `setResponseStatus` or error metadata (`error.status/statusCode/statusText/headers/cause.headers`); success/redirect statuses set before the error are discarded; framing headers never copied; `error.cause` Response contributes status only; HTTP-style errors ≥400 aren't logged; thrown `Response` keeps body/headers. Server-fn errors use a separate RPC serialization path. Source: `S:guide/server-entry-point.md`
  - Same-origin RPC endpoint at `/_serverFn/*` (needs allow-listing in SPA hosts).

## 7. Loading & error states

- **Route-level loading UI**: **Supported.** `pendingComponent` / router `defaultPendingComponent`, shown when `beforeLoad`/`loader` promises are pending longer than `pendingMs` (default **1000ms**) and then for at least `pendingMinMs` (default **500ms**) to avoid flashes. `wrapInSuspense: true` forces a Suspense boundary. Stale-while-revalidate reloads don't show pending UI (unless `staleReloadMode: 'blocking'` or `invalidate({ forcePending: true })`). Server-side: first non-SSR route's pendingComponent is the SSR fallback; SPA shell renders pending fallback. Global indicators via `useRouterState`, `<MatchRoute pending>`. Source: `R:api/router/RouteOptionsType.md`, `R:guide/data-loading.md`, `S:guide/selective-ssr.md`
- **Error boundaries (per route, root/global)**: **Supported.** Per-route `errorComponent({ error, reset })` (`error` typed `unknown` in React — narrow before use; falsy throws passed through), fallback chain route → parent → router `defaultErrorComponent` (default built-in `ErrorComponent`). Catches errors in `validateSearch`, `params.parse`, `beforeLoad`, `loader`, and rendering. `reset()` retries rendering; for loader errors call `router.invalidate()` (reloads + resets boundary). `onError(error)` (load-time; throwing `redirect`/`notFound` from it replaces the error), `onCatch(error)` / router `defaultOnCatch(error, errorInfo)` (render boundary), `disableGlobalCatchBoundary` (let errors bubble to top-level handlers), `CatchBoundary` component. Root: root route `errorComponent` (wrapped by `shellComponent` if defined); custom client entry may wrap `<StartClient/>` in an app ErrorBoundary. Source: `R:guide/data-loading.md`, `S:guide/error-boundaries.md`, `R:api/router/RouterOptionsType.md`, `S:guide/client-entry-point.md`
- **404 / not-found handling**: **Supported.** Unmatched paths (or extra trailing segments) throw automatic not-found; `notFoundMode: 'fuzzy'` (default: nearest matched route with `notFoundComponent`/router default, preserving layouts) or `'root'`. `notFoundComponent` / `defaultNotFoundComponent` (fallback is a deliberately bare `<p>Not Found</p>`); a `notFoundComponent` cannot render `<Outlet>`; leaf routes can't handle path not-found. Manual: `throw notFound({ data, routeId, headers, throw })` from `beforeLoad`/`loader`/server functions/components (components discouraged; `CatchNotFound` component exists); `routeId: rootRouteId` targets root; for `beforeLoad` not-found, required parent loaders still run so the boundary has data; in `notFoundComponent`, `useLoaderData` may be undefined while `useParams/useSearch/useRouteContext` are defined. HTTP status: Next.js migration reference expects "HTTP 404" for a missing post (implies SSR maps notFound to 404; mechanism not described). `NotFoundRoute` deprecated. Source: `R:guide/not-found-errors.md`, `R:api/router/NotFoundErrorType.md`, `S:migrate-from-next-js.md`
- **Helpers (redirect, notFound, error)**: `redirect({ ...NavigateOptions, to | href (external), statusCode, headers, throw })` — return or throw; route-bound `Route.redirect()` / `getRouteApi().redirect()` (typed relative paths); `isRedirect`; `notFound()`/`isNotFound`; no `error()` helper (throw anything; set HTTP status with `setResponseStatus` or error metadata on server). Default redirect status not documented (migration example uses explicit 308). Source: `R:api/router/redirectFunction.md`, `R:api/router/RedirectType.md`, `S:migrate-from-next-js.md`
- **Expected vs unexpected errors**: **Partial.** Redirect/notFound are typed control flow; everything else is an "error". On the server, HTTP-style errors (status ≥400 in error metadata) are treated as expected (not logged) while others are logged and returned as generic 500 JSON (message hidden). Server-function errors propagate to the caller with message. Router state keeps the original thrown value. Source: `S:guide/server-entry-point.md`, `R:guide/data-loading.md`
- **Error reporting hooks**: **Partial.** Client: `defaultOnCatch`, route `onError`/`onCatch`, `router.subscribe` events; server: wrap `createServerEntry({ fetch })` in try/catch around a raw `createStartHandler` handler then `return handleStartError(error)`/rethrow/return own Response (Sentry example); middleware try/catch. No dedicated `onRequestError` instrumentation hook. Source: `S:guide/server-entry-point.md`, `S:guide/observability.md`

Source: `S:guide/rendering-markdown.md`

  - **`transformAssets` (experimental)** on `createStartHandler({ handler, transformAssets })`: string prefix | `{ prefix, crossOrigin }` | callback `(asset: { kind: 'script'|'stylesheet'|'css-url', url, stylesheetHref? }) => string | { href, crossOrigin? } | Promise` | `{ transform | createTransform(ctx: { warmup: true } | { warmup: false, request }), cache = true, warmup = false }`. ## Solid flavor gaps (vs React)
Most Solid Start guide pages are `ref:` stubs that re-render the React page with string replacements (`SS:guide/*.md`), so shared features (server functions, middleware, server routes, selective SSR, SPA, prerender, CSS styling/inlining, early hints, import protection, hosting) are documented for Solid. **Missing for Solid** (no page in `docs/start/config.json` or `SS:`): **Server Components (RSC)**, **Streaming Data from Server Functions**, **ISR**, **CDN Asset URLs (`transformAssets`)**, **Production Checklist**, **Rendering Markdown**, **TanStack Query guide**, and the Comparison / Start-vs-Next.js / Migrate-from-Next.js pages; Router comparison table has no Solid version. Behavioral differences: Solid deferred hydration clears preserved server DOM and mounts a fresh subtree when a gate opens (no React-style early reconciliation); Solid error components receive `Error` (non-Error throws wrapped with `cause`); `<Await>`/`use()` notes are React-specific. Solid has extra example templates (Netlify/Nitro Vite plugins).
