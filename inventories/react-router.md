## 1. Routing

- **Route definition (config-based)**: Supported, stable, and the primary mechanism. `app/routes.ts` is **required** and default-exports a `RouteConfig` array (`satisfies RouteConfig`). Each entry pairs a URL pattern with a route-module file path. The config file is executed (it can be async / use top-level `await`). Helpers from `@react-router/dev/routes`:

  | Helper | Signature / behavior |
  |---|---|
  | `route(path, file, children?)` | Route with URL pattern + module; children nest under the parent path and render into its `<Outlet/>`. An options object (e.g. `{ id }`) can be passed as 3rd arg (from memory, unverified). |
  | `index(file)` | Index route: renders into parent's `<Outlet>` at the parent's URL. Cannot have children. |
  | `layout(file, children)` | Pathless layout: adds nesting/UI but no URL segment. |
  | `prefix(prefix, routes)` | Prepends a path prefix to child routes **without** adding a route to the tree (pure path rewrite; spread with `...prefix()`). |
  | `relative(dir)` | Returns helper set whose file paths resolve relative to `dir`, for splitting route config across files/directories. |

  Root route `app/root.tsx` is **required**, wraps every route in `routes.ts`, and renders the `<html>` document. Route IDs are auto-generated: file path relative to `app/` without extension (`app/root.tsx`→`"root"`, `app/routes/teams.tsx`→`"routes/teams"`). `react-router routes [--json]` prints the tree. Source: docs/start/framework/routing.md, docs/api/framework-conventions/routes.ts.md, docs/api/framework-conventions/root.tsx.md, docs/api/hooks/useRouteLoaderData.md, docs/api/other-api/dev.md
- **File-based routing**: Supported (opt-in package `@react-router/fs-routes`), stable. `flatRoutes({ ignoredRouteFiles?: string[], rootDirectory?: string /* default "routes", relative to app dir */ })` returns a `RouteConfig`; can be spread alongside config routes (`[route("/", "./home.tsx"), ...(await flatRoutes())]`). Conventions ("flat routes", dot-delimited, all files directly in `app/routes`):

  | Convention | Meaning |
  |---|---|
  | `_index.tsx` | Index route of parent (root if top level) |
  | `concerts.trending.tsx` | `.` → `/` in URL **and** creates nesting if a `concerts.tsx` exists |
  | `$city` | Dynamic segment → `params.city` |
  | `($lang)` | Optional segment (dynamic or static); optional segments match eagerly (`/x` matches `/:lang` before `/:productId`) |
  | `$.tsx` / `files.$.tsx` | Splat → `params["*"]`; root `$.tsx` = catch-all (returns **200** unless loader returns `data({}, 404)`) |
  | `_auth.tsx` + `_auth.login.tsx` | Leading `_` = pathless layout route |
  | `concerts_.mine.tsx` | Trailing `_` = keep URL nesting but **opt out of layout nesting** (renders in root) |
  | `[...]` | Escapes special chars: `sitemap[.]xml.tsx`→`/sitemap.xml`, `[[so-weird]].tsx`→`/[so-weird]`, `reports.$id[.pdf].ts`→`/reports/123.pdf` |
  | `folder/route.tsx` | Folder route module; other files in the folder are NOT routes (colocation) |

  Extensions `.js/.jsx/.ts/.tsx`. Source: docs/how-to/file-route-conventions.md
- **Component routes**: Supported but limited — `<Routes>/<Route>` inside components still work in framework mode but "do not participate in data loading, actions, code splitting, or any other route module features". Source: docs/start/framework/routing.md
- **Nested layouts**: Supported. Children render through `<Outlet context?>` (`context` value read with `useOutletContext`). Parent path auto-prefixed to children. Root `Layout` export wraps the default component, `HydrateFallback`, and `ErrorBoundary` (avoids duplicate app shell and remounting `<Links>` stylesheet tags → FOUC). Layouts stay mounted across child navigations (docs tell you to keep a `<ViewTransition>` around the outlet mounted "across navigations; you don't need to key it by location or remount the route tree"). Note: in SSR framework mode the parent's **loader** re-runs on every navigation by default (see §3). Source: docs/start/framework/routing.md, docs/api/framework-conventions/root.tsx.md, docs/api/components/Outlet.md, docs/how-to/view-transitions.md
- **Dynamic segments**: Supported. `:param` (multiple per path allowed, e.g. `c/:categoryId/p/:productId`); typed in `Route.LoaderArgs["params"]`. Child routes inherit parent params. Source: docs/start/framework/routing.md, docs/api/hooks/useParams.md
- **Optional segments**: Supported. `?` suffix on dynamic (`:lang?/categories`) **or static** (`users/:userId/edit?`) segments. Source: docs/start/framework/routing.md
- **Catch-all / splat**: Supported. Path ending `/*` → `params["*"]` (rename via `const { "*": splat } = params`). `route("*", "./catchall.tsx")` as global catch-all; you must throw/return a 404 yourself (`throw new Response("Page not found", { status: 404 })`). Source: docs/start/framework/routing.md
- **Route groups / pathless layouts**: Supported. `layout()` in config; `_leading` underscore in fs-routes; `prefix()` for grouping by URL prefix without a route. Source: docs/start/framework/routing.md, docs/how-to/file-route-conventions.md
- **Parallel routes**: Not found in docs (single outlet per route; no named slots).
- **Intercepting / modal routes**: Partial. `<Link mask>` (framework + data mode, no `unstable_` prefix) navigates the router to one location while displaying another in the URL bar (e.g. `to="/gallery?image=1" mask="/images/1"`); sharing/opening in new tab loads only the masked URL. Relies on `history.state` → "only intended for SPA uses and SSR renders will not respect the masking". Also on `useLinkClickHandler` (`options.mask`). No file-convention interception. Source: docs/api/components/Link.md, docs/api/hooks/useLinkClickHandler.md
- **Typed links / typed params**: Supported via codegen. `href(path, params)` (framework only) is type-checked against the route config (`href("/products/:id", { id })`, optional params allowed: `href("/:lang?/about", { lang: "en" })`). Encoding: param values percent-encoded for a path segment (`/ ? # %`, whitespace, non-ASCII escaped; RFC 3986 path-safe `$ & + , ; = : @` kept); splat values encoded per segment preserving `/`. `<Link to>` itself accepts any string/partial `Path` (not typed). Params typed per route via `+types`. Source: docs/api/utils/href.md, docs/explanation/type-safety.md
- **Search-param handling**: Partial (untyped, unvalidated). `useSearchParams(defaultInit?)` → `[URLSearchParams, setSearchParams]`; `defaultInit` does **not** change URL on first render; `setSearchParams` accepts string/object/array/`URLSearchParams` or a callback, **causes a navigation** (and thus loader revalidation unless `defaultShouldRevalidate: false`), and the callback form does **not** queue like React `setState` (multiple calls in one tick don't compose). `searchParams` is a stable but mutable reference. Server side: `new URL(request.url).searchParams`. `<Form method="get">` serializes inputs into the URL. No schema validation or typed search params found. `docs/how-to/search-params.md` is a hidden empty stub. Source: docs/api/hooks/useSearchParams.md, docs/start/framework/navigating.md
- **Programmatic navigation**: Supported. `useNavigate()` → `navigate(to, options?)` / `navigate(delta)`; in framework/data mode returns `Promise<void>` resolving when navigation completes and has a stable identity (type is `void | Promise<void>`; docs show a module-augmentation workaround).

  | `navigate` option | Modes | Behavior |
  |---|---|---|
  | `replace` | all | replace history entry |
  | `state` | all | `history.state` → `useLocation().state` (not available on server) |
  | `relative` | all | `"route"` (default) or `"path"` |
  | `preventScrollReset` | framework/data | don't scroll to top (with `<ScrollRestoration>`) |
  | `flushSync` | framework/data | wrap DOM update in `ReactDOM.flushSync` |
  | `defaultShouldRevalidate` | — | per-navigation revalidation default (see §3) |
  | `viewTransition` | framework/data | **Deprecated** (use React `<ViewTransition>`) |

  `<Navigate to replace state relative>` component (discouraged; for class components). In loaders/actions prefer `redirect()`. Docs recommend `useNavigate` only for non-user-initiated navigations (inactivity logout, timers). Source: docs/api/hooks/useNavigate.md, docs/api/components/Navigate.md, docs/start/framework/navigating.md, docs/how-to/optimize-revalidation.md
- **`<Link>` props** (full list, framework mode):

  | Prop | Values / default | Behavior |
  |---|---|---|
  | `to` | string or partial `Path` `{pathname, search, hash}` | target |
  | `prefetch` | `"none"` (default) / `"intent"` (hover/focus) / `"render"` / `"viewport"` | Prefetches **both route modules and loader data** via `<link rel="prefetch">`/`modulepreload` tags inserted **after** the `<a>` (breaks `:last-child` selectors → use `:last-of-type`). Framework only. |
  | `discover` | `"render"` (default) / `"none"` | Lazy route discovery: discover route manifest entry when link renders vs only on click. Framework only. |
  | `reloadDocument` | bool | Full document navigation (required for resource routes) |
  | `replace` | bool | replace history entry |
  | `state` | any | history state |
  | `relative` | `"route"` (default) / `"path"` | `..` resolves against route hierarchy (index/layout routes have no path and are skipped) vs URL segments |
  | `preventScrollReset` | bool | keep scroll position on new location (back/forward still restored) |
  | `defaultShouldRevalidate` | bool | default revalidation for this navigation; passed into routes' `shouldRevalidate` if exported |
  | `mask` | `To` | URL masking (see intercepting routes) |
  | `viewTransition` | bool | **Deprecated** |

  Source: docs/api/components/Link.md
- **`<NavLink>`**: adds `className`/`style`/`children` render-props receiving `{ isActive, isPending, isTransitioning }`; default classes `active`, `pending` (pending only in framework/data), `transitioning` (**deprecated**); auto `aria-current="page"`; `end` (only exact match; `to="/"` effectively always `end`); `caseSensitive`; plus all Link props (`prefetch`, `discover`, `preventScrollReset`, `relative`, `reloadDocument`, `replace`, `state`, `viewTransition` deprecated). Source: docs/api/components/NavLink.md
- **Prefetching (strategies)**: Supported. Per-link `prefetch` (above); `<PrefetchPageLinks page="/abs/path" {...linkProps}>` renders `<link rel=prefetch|modulepreload>` for another page's modules **and data** (e.g. while typing a search). Prefetch uses native link elements → bypasses `unstable_fetch` and its auth headers; relies on browser HTTP cache. Lazy route discovery eagerly batches manifest requests for all rendered `<Link>`/`<NavLink>` (and `<Form>`) to avoid navigation waterfalls. Source: docs/api/components/PrefetchPageLinks.md, docs/api/framework-routers/HydratedRouter.md, docs/explanation/lazy-route-discovery.md
- **Scroll restoration**: Supported. `<ScrollRestoration>` (render once, right before `<Scripts>`) emulates browser restoration: new locations scroll to top, back/forward restore. Props: `getKey(location, matches)` (default `location.key`; e.g. return `pathname` to restore on revisits), `storageKey` (sessionStorage key, default `"react-router-scroll-positions"`), `nonce` (defaults to `<ServerRouter nonce>`). Renders an inline `<script>` to prevent scroll flashing on load. Opt-out per navigation via `preventScrollReset`. Hash scrolling: not documented. Source: docs/api/components/ScrollRestoration.md
- **View transitions**: Supported via React. Recommended: wrap the outlet in React's `<ViewTransition>` in a layout (root default export); requires React/React DOM **19.3+**; works because router state updates are wrapped in `startTransition` by default (must not set `useTransitions={false}`; `flushSync` also blocks). Applies to `<Link>`, `<NavLink>`, `<Form>`, `useNavigate`, `useSubmit`. Shared elements via `<ViewTransition name>`. Caveat: React skips view transitions for synchronous `popstate` updates → Back/Forward may not animate. Legacy router-driven `viewTransition` prop/option (wraps in `document.startViewTransition()`), `useViewTransitionState(to, { relative })`, NavLink `isTransitioning`/`.transitioning` are **deprecated** (still work, incl. older React); enabling both systems can interrupt animations. Source: docs/how-to/view-transitions.md, docs/api/hooks/useViewTransitionState.md
- **Route-level code splitting**: Supported, automatic. Each route module is a bundler entry; only modules for matched routes load. `splitRouteModules` (top-level config, **enabled by default** in v8; `false` to opt out, `"enforce"` to fail the build for routes that can't be split due to shared code) further splits `clientLoader`, `clientAction`, `clientMiddleware`, `HydrateFallback` into separate chunks so they download/run in parallel with the component. Server exports (`loader`, `action`, `middleware`, `headers`) are stripped from client bundles. Not supported in RSC framework mode. Source: docs/explanation/code-splitting.md, docs/how-to/react-server-components.md
- **Lazy route discovery (manifest)**: Supported, default. `routeDiscovery: { mode: "lazy" (default), manifestPath: "/__manifest" }` or `{ mode: "initial" }` (full manifest up front). Only routes needed for the SSR page are in the initial manifest; navigation to unknown routes → `/__manifest?version=…&paths=…` request → patch → load modules → navigate. Deployment: the manifest path must reach the React Router handler; CDN cache key must include `version` and `paths`; use custom `manifestPath` for multiple apps on one domain. SPA mode and dev use a full manifest. Source: docs/explanation/lazy-route-discovery.md, docs/api/framework-conventions/react-router.config.ts.md, docs/how-to/route-discovery.md
- **Base path**: Supported. `basename` config key (default `"/"`). `discoverRoutes` applies it; `useFormAction` adds it (strip it when passing to `<Form>`/`fetcher.submit`, which prepend internally). Source: docs/api/framework-conventions/react-router.config.ts.md, docs/api/hooks/useFormAction.md
- **Notable extras**:
  - Index-route targeting `?index`: a `<Form>` with no `action` rendered in an index route posts to `/path?index`; parent vs index action disambiguated by `?index` (applies to `useSubmit`, `fetcher.submit`). Source: docs/explanation/index-query-param.md
  - Navigation blocking: `useBlocker(boolean | ({currentLocation, nextLocation, historyAction}) => boolean)` → `{ state: "unblocked"|"blocked"|"proceeding", location, proceed(), reset() }` (in-app only; not hard reloads/cross-origin); `unstable_usePrompt({ when, message })` (window.confirm; will stay unstable — browser inconsistencies); `useBeforeUnload`. Source: docs/api/hooks/useBlocker.md, docs/api/hooks/usePrompt.md, docs/how-to/navigation-blocking.md
  - `handle` export + `useMatches()` for breadcrumbs/ancestor-rendered metadata. Source: docs/how-to/using-handle.md
  - `unstable_useRouterState()` → `{ active: {location, searchParams, params, matches, type}, pending: {…, state, formMethod, formAction, formEncType, formData, json, text} }` consolidating 6 hooks; pending `params`/`matches` not otherwise accessible. Source: docs/api/hooks/useRouterState.md
  - `useTransitions` prop on `<HydratedRouter>`: default wraps state updates in `startTransition`; `false` opts out (for `useSyncExternalStore` apps); `true` (React 19) also wraps `<Link>`/`<Form>` navigations in async Transitions and surfaces in-flight state (`navigation`, `revalidation`, `actionData`, `fetchers`) through `useOptimistic`. Docs say they "plan to make the opt-in behavior the default in v8" — current default not confirmed. Source: docs/explanation/react-transitions.md
  - Automatic race-condition handling: interrupted navigations/submissions cancel in-flight requests (browser-like); a fetcher cancels its own prior request; stale revalidations are discarded when a later-started one lands first. Source: docs/explanation/race-conditions.md, docs/explanation/concurrency.md
  - New matcher `future.unstable_routePatternMatching` (`@remix-run/route-pattern`, positional specificity ranking) is **data mode only**. Source: docs/upgrading/future.md
  - Accessibility: `<NavLink>` `aria-current`; focus management and route-change live announcements are **not** automatic (docs say app must handle). Source: docs/how-to/accessibility.md

## 2. Rendering modes

- **SSR**: Supported, default (`ssr: true`). Document requests run server middleware → all matched loaders (parallel) → render `<ServerRouter context url nonce?>` in `entry.server.tsx` (optional on Node; a default is used; `react-router reveal` ejects it; **required on non-Node runtimes** such as Cloudflare). Default entry uses `renderToPipeableStream` on Node and `renderToReadableStream` elsewhere; `future.unstable_enableNodeReadableStream` makes the default use `renderToReadableStream` everywhere (no effect if you have a custom entry). `entry.server` default export signature: `handleRequest(request, responseStatusCode, responseHeaders, routerContext /* EntryContext */)` → `Response` (you control status, headers, HTML stream). `<ServerRouter>` props: `context` (EntryContext: manifest, route modules, data), `url`, `nonce` (applied to React Router inline scripts; default for `<Links>`, `<Scripts>`, `<ScrollRestoration>`). Omitting `<Scripts/>` yields a no-JS multi-page app. Source: docs/start/framework/rendering.md, docs/api/framework-conventions/entry.server.tsx.md, docs/api/framework-routers/ServerRouter.md, docs/upgrading/future.md, docs/api/components/Scripts.md
- **Streaming SSR**: Supported, stable. Mechanism: loaders return an **object containing un-awaited promises** (a bare top-level promise is not allowed) → rendered with `<React.Suspense>` + `<Await>` or `React.use(promise)`. Behavior details:
  - React Router waits for **all loaders to settle (`Promise.all`)** before streaming begins; promises nested in the returned objects continue streaming afterwards.
  - Outstanding streamed promises are rejected after **4950 ms** by default; override with `export const streamTimeout` (ms) in `entry.server.tsx`; docs recommend aborting the React render ~1 s later (`setTimeout(abort, streamTimeout + 1000)`).
  - Node caveat: a streamed promise that rejects **before** all loaders settle is an unhandled rejection and can crash the process → register `process.on("unhandledRejection")`.
  - Default entry flushes on `onShellReady`; `handleError` only sees shell errors; errors in later streamed chunks must be handled in `onError` yourself.
  - `<Await>` props: `resolve` (React Router promise tracking; `errorElement` also catches render errors in children), `unstable_promise` (uses React `use()`; accepts promise-likes without modifying them; `errorElement` catches only rejections; render errors go to nearest React boundary) — pass exactly one; `children` (element or render function `(value) => …`; `useAsyncValue()`/`useAsyncError()` in children); `errorElement` (if omitted, rejection bubbles to the route `ErrorBoundary`). Plan: stabilize `<Await promise>`, deprecate `resolve` during v8, drop it in v9.
  - Actions may also return promises. Resource routes can stream promises to fetchers via `data()`.
  Source: docs/how-to/suspense.md, docs/api/components/Await.md, docs/api/framework-conventions/entry.server.tsx.md, docs/how-to/resource-routes.md
- **Static pre-rendering**: Supported, stable. `prerender` config:

  | Form | Behavior |
  |---|---|
  | `true` | all static paths from `routes.ts` (no dynamic params) |
  | `string[]` | explicit paths incl. dynamic values |
  | `async ({ getStaticPaths }) => string[]` | compute paths; `getStaticPaths()` returns the static ones |
  | `{ paths, concurrency }` | as above with parallel rendering (default sequential, 1 at a time) |

  Build issues a synthetic `new Request()` per path through the normal handler (same `loader`s; no extra API). Output in `build/client`: `<path>/index.html` + `<path>.data` (client-navigation payload). Not written in dev. Combinations: with `ssr: true` → non-prerendered paths SSR at runtime; with `ssr: false` → static hosting, plus SPA fallback (`index.html`, or `__spa-fallback.html` if `/` is prerendered); with `ssr: "unstable_api-only"` (experimental) → static docs + runtime loader/action server. `ssr:false` build-time validation: `action`/`headers` exports forbidden on all routes; `loader` only on prerendered routes (root only in pure SPA mode); a prerendered parent with loader + non-prerendered children needs all children prerendered or a parent `clientLoader`. Source: docs/how-to/pre-rendering.md, docs/start/framework/rendering.md
- **Client-only routes / full SPA mode**: Supported.
  - **SPA mode** = `ssr: false` without `prerender`: build still SSRs the **root route only** into `index.html` (so `@react-router/node` dependency is still required and code must be SSR-safe; no `window` in initial render). Root may have a `loader` (runs at **build time**; data passed to `HydrateFallback`'s `loaderData`) and a `HydrateFallback` shown while the SPA boots. All other routes use `clientLoader`/`clientAction`. Host must rewrite all URLs to `index.html` (`/* /index.html 200`). Re-enabling SSR later needs no UI changes.
  - **Per-route client rendering under SSR**: a route exporting only `clientLoader` (no `loader`) implies `clientLoader.hydrate = true`; SSR renders the nearest `HydrateFallback` (bubbling up to ancestors if the route has none), never the component, until the client loader finishes.
  - **API-only mode** (`ssr: "unstable_api-only"`, experimental, not in RSC): runtime server for loaders/actions/route discovery but no production document SSR; root-only `index.html` shell built from root `HydrateFallback`; server `loader`/`action` usable without client wrappers; prod handler returns **404 for document requests**; deploy `build/client` + server; `react-router-serve` routes automatically. `unstable_apiServerOrigin: "https://api.example.com"` sends `.data` + `/__manifest` requests to a separate origin (origin only; CORS + `allowedActionOrigins` needed; default `same-origin` credentials, no cross-origin cookies unless custom fetch).
  Source: docs/how-to/spa.md, docs/start/framework/rendering.md, docs/explanation/hydration.md, docs/how-to/client-data.md
- **Partial hydration (islands / server components)**: Partial — **React Server Components, experimental** (`unstable_`), framework and data modes. RSC framework mode: Vite plugin `unstable_reactRouterRSC` + peer `@vitejs/plugin-rsc` (placed after); template `unstable_rsc-framework-mode`. Features: route `ServerComponent` export (server-rendered; mutually exclusive with `default`), counterparts `ServerErrorBoundary`/`ServerLayout`/`ServerHydrateFallback` (vs client `ErrorBoundary`/`Layout`/`HydrateFallback`); loaders/actions may return React elements (server-only render); `"use client"` modules for interactivity; `"use server"` Server Functions with automatic route revalidation after call; `unstable_getRequest()` inside server functions; client annotations (`clientLoader`, `clientAction`, `shouldRevalidate`) still allowed. Limits: `.server`/`.client` file conventions **not built in** (use `import "server-only"`/`"client-only"` or `vite-env-only` `denyImports`); unsupported config keys `buildEnd`, `presets`, `serverBundles`, `splitRouteModules`; API-only mode, custom fetch, custom route discovery unsupported; MDX routes need `@mdx-js/rollup` ≥3.1.1 and RSC-safe components. Custom entries `app/entry.rsc.ts` (default export with `fetch`), `app/entry.ssr.ts` (`generateHTML`), `app/entry.client.tsx`; `react-router reveal entry.rsc|entry.ssr|entry.client`. No islands / server islands outside RSC. Source: docs/how-to/react-server-components.md, docs/start/framework/rendering.md, docs/how-to/route-discovery.md, docs/how-to/custom-fetch.md
- **Static shell with dynamic holes (PPR-like)**: Not found in docs. (Closest: streaming with `<Await>`; prerendered pages + `clientLoader` for dynamic parts; API-only mode prerendered shell + runtime loaders.)
- **Per-route rendering-mode control**: Partial. `ssr` is global ("Though it's a global setting, individual routes can still be statically pre-rendered"); prerender is per-**path** list; per-route client-only data via `clientLoader`/`HydrateFallback`; per-route RSC via `ServerComponent` vs `default` (experimental). No per-route `ssr:false`/`dynamic` flag. Source: docs/start/framework/rendering.md, docs/how-to/pre-rendering.md
- **Hydration strategies**: Full-document hydration only. `entry.client.tsx` (optional; default provided; `react-router reveal entry.client`): `startTransition(() => hydrateRoot(document, <StrictMode><HydratedRouter/></StrictMode>))`. Server loader data is serialized into the HTML and reused on hydration (client loaders don't run unless `clientLoader.hydrate = true` or no server loader). `HydrateFallback` rules: only on initial load (never on client navigations); only relevant with `hydrate=true` or client-only loader; cannot render `<Outlet/>`. No lazy/visible/idle hydration directives. Source: docs/api/framework-conventions/entry.client.tsx.md, docs/explanation/hydration.md, docs/start/framework/route-module.md
- **Notable extras**:
  - `<HydratedRouter>` props: `getContext` (fresh client `context` per navigation/fetch for `clientLoader`/`clientAction`/`clientMiddleware`), `onError` (see §7), `instrumentations` (§12), `useTransitions` (§1), `unstable_fetch` (§3). Source: docs/api/framework-routers/HydratedRouter.md, docs/how-to/instrumentation.md, docs/explanation/react-transitions.md
  - Progressive enhancement is a design principle: SSR + `<Link>`/`<Form>` work before JS loads; app works with `<Scripts>` omitted. Source: docs/explanation/progressive-enhancement.md

## 3. Data loading

- **Where data is fetched**: Route-module functions. `loader` (server only; stripped from client bundle; runs on document SSR, on client navigations via automatic `fetch` to a `.data` URL, and at build time for prerender), `clientLoader` (browser only), RSC async server components (experimental). Components receive data as `loaderData` prop (typed) or via hooks. Source: docs/start/framework/route-module.md, docs/start/framework/data-loading.md
- **Loader args**: `request` (Fetch `Request`; with v8 pass-through semantics `request.url` is the raw HTTP URL including `.data` suffix/internal params — inferred v8 default of `v8_passThroughRequests`), `url` (normalized `URL` with `.data`, `?index`, `?_routes` stripped), `params` (typed), `context` (`RouterContextProvider`). `clientLoader` args add `serverLoader()` (calls the server loader via fetch); `clientAction` adds `serverAction()`. Source: docs/upgrading/v7.md, docs/start/framework/route-module.md, docs/how-to/client-data.md
- **Loader execution model**: Matched route loaders run **in parallel** (no parent→child waterfall); middleware runs sequentially before them. Consequence spelled out: a parent loader **cannot protect** child loaders/actions (they can be requested independently via fetchers/partial revalidation) — use server middleware or per-loader auth. `loader` + `clientLoader` together: server loader for SSR/prerender, client loader for subsequent navigations; `clientLoader.hydrate = true as const` forces it on hydration (pair with `HydrateFallback`; or omit fallback to SSR the component then run client loader, which must return matching data to avoid hydration errors). Patterns documented: skip-the-server-hop (BFF direct API on client nav), fullstack state (merge server + IndexedDB), client-side caching. Source: docs/start/framework/data-loading.md, docs/how-to/client-data.md
- **Wire protocol**: Data requests use `.data` URLs (`/a/b/c.data`; root `/_root.data` → `/_.data`; trailing-slash URLs `/a/b/c/_.data` under the v8 trailing-slash-aware behavior) with internal search params (`?_routes`, `?index`); payload is **Turbo Stream-encoded**, supporting promises, `Map`, `Set`, `Date`, etc. (aligned with RSC serializable types). Docs don't use the term "Single Fetch"; one `.data` request per navigation covering needed loaders (from memory, unverified). Source: docs/upgrading/v7.md, docs/how-to/custom-fetch.md, docs/start/framework/data-loading.md
- **Request deduplication**: Not found in docs (no fetch memoization). Related: navigation/fetcher cancellation and stale-revalidation discarding (§1 extras).
- **Passing server data to client components**: `loaderData`/`actionData`/`params`/`matches` props on route component (`Route.ComponentProps`); hooks `useLoaderData()` (closest route), `useRouteLoaderData(routeId)` (any route; may be `undefined`; use in `ErrorBoundary`/`Layout`), `useMatches()` (`matches[i].loaderData`, `handle`), `useActionData()` (last POST navigation submission, else `undefined`). `useLoaderData` is not permitted in `ErrorBoundary`. Source: docs/start/framework/route-module.md, docs/api/hooks/*.md, docs/api/framework-conventions/root.tsx.md
- **Client-side data cache**: Not supported as a built-in cache. Docs say most client caching is "redundant" due to revalidation; options: `clientLoader` with your own cache (memory/localStorage) invalidated in `clientAction`; HTTP `Cache-Control` on loaders via `headers`; experimental `unstable_fetch` with `cache: "force-cache"` for POP (back/forward) navigations ("not a router-managed data cache"). Source: docs/explanation/state-management.md, docs/how-to/client-data.md, docs/how-to/custom-fetch.md
- **Deferred / streamed data**: Supported (see §2 Streaming): return `{ critical, nonCritical: promise }`; consume via `<Await>`/`React.use`; `streamTimeout`. Source: docs/how-to/suspense.md
- **Dependency tracking & invalidation (revalidation)**: Supported, router-driven (no fine-grained dependency tracking). Defaults:

  | Mode | Navigations (GET `<Link>`) | Successful submissions (2xx) | Failed submissions (4xx/5xx) |
  |---|---|---|---|
  | Framework **with SSR** | **all active loaders revalidate on every navigation** (opt-out) | all active loaders revalidate | no revalidation |
  | Framework SPA mode / Data mode | only routes whose **params** changed, or any **search param** change; same exact URL = refresh → all | all active loaders | no revalidation |

  Each matched route decides independently (a child skipping doesn't skip ancestors). `fetcher.load` data revalidates only after action submissions and explicit `useRevalidator`, not on param/search navigations. Plain `fetch()` to a resource route does **not** revalidate. Rationale given: lets middleware and loaders share one request context. Source: docs/how-to/optimize-revalidation.md, docs/start/framework/route-module.md
- **`shouldRevalidate` export** (per route; opt out of this route's loader only): receives `ShouldRevalidateFunctionArgs`: `currentUrl`, `nextUrl`, `currentParams`, `nextParams`, `formMethod`, `formAction`, `formData`, `json`, `text`, `actionResult`, `actionStatus`, `defaultShouldRevalidate`. Return `boolean`. Always-`false` also disables param-change and `useRevalidator` revalidation (warned against). In SPA mode behaves like data mode. Call-site override `defaultShouldRevalidate={false}` on `<Form>`, `<Link>`, `<fetcher.Form>` and option on `useSubmit`, `fetcher.submit`, `useNavigate`, `useSearchParams`' setter: used directly for routes without `shouldRevalidate`, otherwise passed as the arg (route has final say — e.g. root still reloads after `fetcher.submit` unless root opts out). Source: docs/how-to/optimize-revalidation.md, docs/start/framework/route-module.md, docs/api/components/Form.md, docs/api/components/Link.md
- **Manual revalidation**: `useRevalidator()` → `{ revalidate(): Promise<void>, state }` (window focus, polling). Dev: Hot Data Revalidation re-runs loaders when server code changes. Source: docs/api/hooks/useRevalidator.md, docs/api/other-api/dev.md
- **Access to request context**: `context` arg (`RouterContextProvider`) populated by middleware (`context.set(key, value)` / `context.get(key)` with `createContext<T>(defaultValue?)` — reading an unset key without default **throws**) and seeded by custom servers via `getLoadContext(req, res)` returning a `RouterContextProvider` (or Cloudflare `requestHandler(request, routerContext)`). Request headers via `request.headers`; cookies via `createCookie(name, options).parse(request.headers.get("Cookie"))`. `AsyncLocalStorage` works alongside (recommended for RSC). Context is **per HTTP request**: on the server, an action and loaders share context only for document POSTs (client-side submissions send separate POST + GET). Source: docs/how-to/middleware.md, docs/api/utils/createContext.md, docs/api/utils/RouterContextProvider.md, docs/api/other-api/adapter.md, docs/explanation/sessions-and-cookies.md
- **Fetchers (non-navigation data loading)**: `useFetcher({ key? })` → `FetcherWithComponents`: `state` (`"idle"|"loading"|"submitting"`), `data`, `formData`, `formAction` (and `formMethod`, etc.), `<fetcher.Form>`, `fetcher.load(href)` (calls a route's loader), `fetcher.submit(target, options)` (target = form element/event form, `FormData`, object; `encType` incl. `"application/json"`), `fetcher.reset()`. Default key is component-scoped; a custom `key` shares fetcher state across components. `useFetchers()` lists all in-flight fetchers with `key`. Type via `useFetcher<typeof loader>()` with `import type`. A fetcher cancels its own pending request when called again. Source: docs/api/hooks/useFetcher.md, docs/api/hooks/useFetchers.md, docs/how-to/fetchers.md, docs/explanation/race-conditions.md
- **Notable extras**:
  - `unstable_fetch` on `<HydratedRouter>` (experimental, not RSC): custom `fetch` for JS-issued `.data`/manifest requests; receives `Request` + `unstable_RouterFetchContext` `{ type: "manifest"|"initialization"|"navigation"|"fetcher"|"revalidation", fetcherKey, navigationType: "PUSH"|"REPLACE"|"POP"|null }`; read once at router creation; must return the response body unconsumed. Does **not** intercept document requests, server-side loaders, assets, your own `fetch` in client loaders, or native prefetches. Use cases documented: auth headers, cross-origin credentials, traversal cache, retrying safe GETs. Source: docs/how-to/custom-fetch.md
  - `dataStrategy` (custom loader execution, with `unstable_initiator`/`unstable_navigationType`) is **data mode only**; framework mode exposes metadata via `unstable_fetch`. Source: docs/how-to/data-strategy.md
  - Auth guidance explicitly says parent loaders don't protect children. Source: docs/start/framework/data-loading.md

## 4. Mutations

- **Form handling without JS (progressive enhancement)**: Supported, stable. `<Form>` renders a native `<form>`; before JS loads the browser submits it normally (GET/POST only); after hydration React Router intercepts, submits via `fetch`, sets `useNavigation` pending state, and revalidates. `<Form>` props:

  | Prop | Values / default | Behavior |
  |---|---|---|
  | `action` | URL; default = **closest route in context** (not current URL) | target route action (`?index` auto-added in index routes) |
  | `method` | `"get"` (default) / `"post"` / `"put"` / `"patch"` / `"delete"` | non-GET/POST lose progressive enhancement; GET navigates with `URLSearchParams` |
  | `encType` | `"application/x-www-form-urlencoded"` (default) / `"multipart/form-data"` / `"text/plain"` | body encoding |
  | `navigate` | `true` default; `false` | submit via internal fetcher (no history entry) |
  | `fetcherKey` | string | with `navigate={false}`, expose state to `useFetcher({ key })` elsewhere |
  | `discover` | `"render"` default / `"none"` | lazy route discovery timing |
  | `preventScrollReset` | bool | keep scroll after navigation |
  | `relative` | `"route"` / `"path"` | action resolution |
  | `reloadDocument` | bool | full document submission (no client routing) |
  | `replace` | bool | replace history entry |
  | `state` | any | history state |
  | `defaultShouldRevalidate` | bool | per-submission revalidation default |
  | `viewTransition` | bool | **Deprecated** |

  Source: docs/api/components/Form.md, docs/explanation/progressive-enhancement.md
- **Server functions / RPC / actions**: Supported. `action` export (server only, stripped from client) handles non-GET submissions to the route; `clientAction` (browser only) **takes priority** over `action` when both exist and can call `serverAction()`. Only **one** action runs per submission (unlike loaders). Invocation: `<Form method="post">` (navigation + history entry), `useSubmit()(target, options)` (imperative, navigation), `<fetcher.Form>` / `fetcher.submit()` (no navigation). `useSubmit` options: `method`, `action`, `encType` (incl. `application/json`, `text/plain`), `navigate`, `fetcherKey`, `replace`, `state`, `preventScrollReset`, `relative`, `flushSync`, `defaultShouldRevalidate`, `viewTransition` (deprecated) — beyond `defaultShouldRevalidate`/`viewTransition` this list is from memory, unverified. RPC-style "server functions" exist only in RSC mode (`"use server"`, experimental; docs warn to treat each as a public endpoint — route middleware does not protect them). Source: docs/start/framework/actions.md, docs/api/hooks/useSubmit.md, docs/how-to/react-server-components.md, docs/how-to/middleware.md
- **Pending / error / validation-error state**: Supported. Navigation submissions: `useNavigation()` → `state` (`idle|loading|submitting`), `location`, `formMethod`, `formAction`, `formEncType`, `formData`, `json`, `text` (field list per docs/api/hooks/useRouterState.md mapping). Fetchers: `fetcher.state/formData/formAction/data`. Validation errors: return `data({ errors }, { status: 400 })` → `actionData` prop / `fetcher.data`; **non-2xx action results skip revalidation**. Thrown errors/`throw data()` go to `ErrorBoundary`. No built-in schema validation. Source: docs/start/framework/pending-ui.md, docs/how-to/form-validation.md, docs/explanation/form-vs-fetcher.md
- **Optimistic UI**: Supported (manual). Read submitted values from `fetcher.formData` / `navigation.formData` and render the predicted state; `useFetchers()` lets distant components participate; with `useTransitions` + React 19 `useOptimistic` integration. No automatic rollback API (state reverts when the fetcher returns to idle with revalidated data). Source: docs/start/framework/pending-ui.md, docs/how-to/fetchers.md, docs/api/hooks/useFetchers.md, docs/explanation/react-transitions.md
- **Data refresh after mutation**: Automatic. After a successful (2xx) action, **all active loaders on the page revalidate** (incl. after `fetcher.submit` and resource-route actions called via `<Form>`/fetcher); opt-outs via `shouldRevalidate` / `defaultShouldRevalidate`. Concurrent fetcher submissions each trigger revalidation; fresher responses commit, older in-flight revalidations are cancelled. RSC server-function calls auto-revalidate the route. Source: docs/start/framework/actions.md, docs/how-to/optimize-revalidation.md, docs/explanation/concurrency.md
- **Redirects after mutation**: Supported. `redirect(url, init?)` (default **302**, sets `Location`; `init` = status number or `ResponseInit`), `replace(url, init?)` (client uses `history.replaceState`), `redirectDocument(url, init?)` (forces full document reload, e.g. logout). All accept absolute/external URLs — docs warn to validate user input (open-redirect). Can be returned or thrown from loaders, actions, middleware. Source: docs/api/utils/redirect.md, docs/api/utils/replace.md, docs/api/utils/redirectDocument.md, docs/start/framework/navigating.md
- **File uploads**: Partial (library-assisted). Requires `encType="multipart/form-data"`. Docs use `@remix-run/form-data-parser` `parseFormData(request, uploadHandler)` (streaming; handler called per file) and `@remix-run/file-storage` (`LocalFileStorage`) plus a resource route that streams the stored file back. No built-in size limits documented. Source: docs/how-to/file-uploads.md
- **Multiple actions per page**: Supported by targeting different routes (`action="/some/route"`, resource routes) or branching on a submitted field (e.g. `intent`) within one action; fetchers allow many concurrent submissions. One `action` export per route. Source: docs/start/framework/actions.md, docs/explanation/concurrency.md, docs/how-to/optimize-revalidation.md
- **CSRF protection built in**: Partial. Origin validation for action submissions to **UI routes** (not resource routes): `allowedActionOrigins` config (micromatch globs, `*`/`**`, e.g. `"*.example.com"`; can be overridden at runtime on the server build object in a custom server). Dev/preview servers honor `X-Forwarded-Proto` "allowing same-origin action submissions to pass origin validation". No CSRF tokens. Docs advise performing mutations in actions, never loaders. RSC: `matchRSCServerRequest({ allowedActionOrigins })`. Source: docs/api/framework-conventions/react-router.config.ts.md, docs/api/other-api/dev.md, docs/explanation/sessions-and-cookies.md, docs/api/rsc/matchRSCServerRequest.md
- **Notable extras**:
  - `<Form>` vs fetcher decision guide: use `<Form>` when URL/history should change, fetchers otherwise. Source: docs/explanation/form-vs-fetcher.md
  - Navigation blocking for dirty forms (`useBlocker`). Source: docs/how-to/navigation-blocking.md

## 5. Caching & revalidation

- **Page/HTML caching**: Partial — via HTTP headers only. Set `Cache-Control` from the route `headers` export (e.g. `"max-age=300, s-maxage=3600"`) for CDN/browser caching; prerendered pages are static files. No built-in server HTML cache. Source: docs/start/framework/route-module.md, docs/how-to/headers.md
- **Time-based revalidation (ISR)**: Not supported built-in (not found in framework docs). RSC data-mode guide notes you "can leverage the HTML generation for … ISR" in a custom setup. Source: docs/how-to/react-server-components.md
- **On-demand revalidation (by path/tag)**: Not supported for server caches (no cache to purge). Client-side "revalidation" means re-running loaders (§3). Source: docs/how-to/optimize-revalidation.md
- **Data-level / function-level caching**: Not supported built-in. Docs recommend server-side caches or backend optimization over client caches. Source: docs/explanation/state-management.md
- **Client navigation cache**: Not supported (no router cache). In SSR framework mode loaders refetch on every navigation by default; reuse comes only from `shouldRevalidate` opt-outs, custom `clientLoader` caches, the browser HTTP cache (honored by `.data` fetches and prefetch `<link>`s), or experimental `unstable_fetch` `force-cache` on back/forward. Source: docs/how-to/optimize-revalidation.md, docs/how-to/custom-fetch.md, docs/how-to/client-data.md
- **HTTP cache-header helpers**: Partial (header plumbing, no cache abstractions). `headers` export (`HeadersArgs`: `parentHeaders`, `loaderHeaders`, `actionHeaders`; also `errorHeaders` (from memory, unverified)) returns `Headers` or `HeadersInit`. Rules: only the **deepest matching route's** headers are sent — merge manually with `parentHeaders.append/set`; loader/action headers set via `data(value, { headers })` are **not** sent unless returned from `headers`; exception: `Set-Cookie` from parent `headers`/`loader`/`action` is preserved automatically. Global headers in `entry.server` (`responseHeaders`), in middleware (`response.headers.set` after `next()`), and for `.data` responses via `handleDataRequest`. Source: docs/how-to/headers.md, docs/how-to/middleware.md, docs/api/framework-conventions/entry.server.tsx.md
- **Preview / draft mode bypass**: Not found in docs.
- **Notable extras**: Lazy-discovery manifest endpoint is CDN-cacheable if the cache key includes `version` + `paths`. `v8_trailingSlashAwareDataRequests` changed `.data` URL shapes — CDN rewrite rules matching `.data` must handle `/_.data`. Source: docs/explanation/lazy-route-discovery.md, docs/upgrading/v7.md

## 6. Server & API

- **API routes / endpoints**: Supported as **resource routes** (stable): any route module exporting `loader` and/or `action` but **no default component**. GET → `loader`; POST/PUT/PATCH/DELETE → the single `action` (branch on `request.method`); no per-method exports. Return a `Response` (recommended for external consumers) or `data()` (for fetchers/forms; enables streaming promises). Link with `<a>` or `<Link reloadDocument>` (client routing would fail with an error message). fs-routes escaping enables extension URLs (`reports.$id[.pdf].ts`). Error semantics: thrown non-Response value → `handleError` + **500**; returned or thrown `Response`/`data()` with any 4xx/5xx = "successful" response, no `handleError`; when called from a fetcher/`<Form>`, thrown errors go to the nearest UI `ErrorBoundary`. Calling a resource action through `<Form>`/fetcher revalidates page loaders; plain `fetch()` does not. Source: docs/how-to/resource-routes.md, docs/how-to/file-route-conventions.md
- **Middleware**: Supported, **stable in v8** (was `future.v8_middleware` in v7). Exports: `middleware: Route.MiddlewareFunction[]` (server) and `clientMiddleware: Route.ClientMiddlewareFunction[]` (browser). Signature `({ request, context, params }, next)`.
  - **Ordering**: nested chain root → parent → child on the way down; leaf's `next()` runs the loaders/action (and on document requests renders HTML); then unwinds child → root. Global middleware = root route's `middleware`. No path matchers; docs warn against `url.pathname.startsWith("/admin")` gating (encoding bypass) — attach to the protected route/layout instead.
  - **`next()`**: callable **once** (second call throws). Server middleware **must return** the `Response`; if you don't call `next()` it's called automatically (fire-and-continue). Client `next()` resolves to the `dataStrategy` results (`Record<routeId, DataStrategyResult>`), not a Response, read-only.
  - **Capabilities**: short-circuit by throwing `redirect()`/Response; set typed context for loaders; read/set response headers after `next()` (don't touch body); post-process by status (e.g. CMS 404 → redirect).
  - **Errors**: a throw in middleware is caught and rendered by the appropriate `ErrorBoundary`; `next()` itself does not throw — it returns the error response (e.g. status 500) so ancestor middleware still runs (e.g. committing sessions). Throw-before-`next()` vs throw-after-`next()` selects different boundaries.
  - **When server middleware runs**: on **every document request** (even without loaders); on client navigations/fetcher calls **only when a `.data` request is made** (i.e. some loader/action must run on the server); trick: add an empty `loader` to force auth middleware on every navigation. Client middleware runs on every client navigation regardless of loaders.
  - Prerender/SPA: server middleware runs at build time for prerendered paths (inferred); resource routes also run middleware (from memory, unverified).
  Source: docs/how-to/middleware.md, docs/start/framework/route-module.md, docs/upgrading/v7.md
- **Request context (cookies, headers, locals)**: Supported. `request` is a standard Fetch `Request` (`request.headers.get(...)`), `context` = `RouterContextProvider` with `createContext<T>()` keys (type-safe replacement for the old untyped `AppLoadContext` object), seeded by `getLoadContext` (Express adapter `createRequestHandler({ build, getLoadContext(req, res) })`) or passed directly (`requestHandler(request, routerContext)` for Cloudflare: `env` + `ctx`). Cookies: `createCookie(name, { secrets?, …Set-Cookie attributes })` → `Cookie` with `parse()`/`serialize()` (attributes settable at create or serialize time; signed when `secrets` given; rotate by prepending secrets — old ones still verify); `isCookie`. `url` arg for the normalized URL. Source: docs/how-to/middleware.md, docs/api/other-api/adapter.md, docs/api/utils/createCookie.md, docs/explanation/sessions-and-cookies.md, docs/how-to/headers.md
- **Streaming responses and SSE**: Partial. Resource routes can return any `Response`, including streamed bodies (docs show streaming a stored file). SSE helpers: Not found in docs. Streamed loader data via Turbo Stream (§3). Source: docs/how-to/file-uploads.md, docs/how-to/resource-routes.md
- **Running work after the response (waitUntil/after)**: Not found in docs. On Cloudflare the adapter example puts `ctx: ExecutionContext` into router context (so `ctx.waitUntil` is reachable by user code); no framework API. Source: docs/api/other-api/adapter.md
- **Server-only code boundaries**: Supported. `*.server.ts` files and `.server/` directories: **build fails** if they end up in the client module graph. `*.client.ts` / `.client/` directories: excluded from server bundles; exports are `undefined` on the server (use only in effects/handlers). Route modules themselves must not be named `.server`/`.client`. Server-only route exports (`loader`, `action`, `middleware`, `headers`) are tree-shaken from client bundles so server imports used only there are safe. Finer control: `vite-env-only`. RSC mode: `import "server-only"` / `"client-only"` instead. Source: docs/api/framework-conventions/server-modules.md, docs/api/framework-conventions/client-modules.md, docs/explanation/code-splitting.md, docs/how-to/react-server-components.md
- **Notable extras**:
  - Built-in internal endpoints: `.data` (loader/action data), `/__manifest` (route discovery). Source: docs/upgrading/v7.md, docs/explanation/lazy-route-discovery.md
  - `@react-router/serve`: zero-config production Express server (`compression`, `express.static`, `morgan`), env `HOST`, `PORT`; intentionally **not configurable** (migrate to `@react-router/express` instead); in development purges `require` cache per request (module-scope state resets, side effects persist). Source: docs/api/other-api/serve.md
  - BFF architecture explicitly supported (loaders/actions `fetch` existing backends). Source: docs/explanation/backend-for-frontend.md
  - CSP nonces: `<ServerRouter nonce>` + `renderTo*Stream({ nonce })`; component `nonce` props override. Source: docs/how-to/security.md

## 7. Loading & error states

- **Route-level loading UI**: Partial. No per-route loading component/file convention for navigations: by default the **old page stays rendered until all next-page loaders resolve**; app code renders pending UI from `useNavigation()` (global, e.g. `Boolean(navigation.location)`), `<NavLink>` `isPending`/`.pending` class (local), `fetcher.state`. Per-section loading via `<Suspense>` + streamed promises. `HydrateFallback` = route-level fallback only during initial load/hydration with client loaders. Source: docs/start/framework/pending-ui.md, docs/explanation/hydration.md
- **Error boundaries**: Supported. `ErrorBoundary` export per route; framework mode passes `error` as a prop (`Route.ErrorBoundaryProps`), or use `useRouteError()`. Catches errors from loaders, actions, middleware, component render, `headers`, `links`, `meta`. The **closest** ancestor route with an `ErrorBoundary` renders (in place of that route's component, parents stay rendered), e.g. error in `invoices.tsx` without boundary → `app.tsx`'s boundary. Root boundary recommended; root `Layout` wraps it (if `Layout` itself throws, React Router falls back to a minimal built-in boundary). `<Await errorElement>` for streamed promise errors (else bubbles to route boundary). RSC: `ServerErrorBoundary`. Source: docs/how-to/error-boundary.md, docs/start/framework/route-module.md, docs/api/framework-conventions/root.tsx.md, docs/api/components/Await.md
- **404 / not-found handling**: Partial. Mechanism is throwing `data(null, { status: 404 })` / `new Response(…, { status: 404 })` from a loader → `ErrorBoundary` with `isRouteErrorResponse(error)` (`status`, `statusText`, `data`). Unmatched URLs: add a splat catch-all route (`route("*")` / `$.tsx`) that throws/returns 404 (catch-all otherwise returns **200**). Default behavior for URLs with no matching route (404 rendered by root `ErrorBoundary`) is from memory, unverified. Source: docs/start/framework/routing.md, docs/how-to/file-route-conventions.md, docs/how-to/error-boundary.md, docs/how-to/status.md
- **Helpers**: `redirect()`, `replace()`, `redirectDocument()` (§4); `data(value, init?: number | ResponseInit)` → `DataWithResponseInit` (status/headers without serializing to a Response; returnable or throwable); `isRouteErrorResponse(error)` (type guard for 4xx/5xx thrown Responses/`data`). No `notFound()`/`error()` helpers (use `throw data(…, 404)`). Status codes for normal responses via `return data(value, { status })`. Source: docs/api/utils/data.md, docs/api/utils/isRouteErrorResponse.md, docs/how-to/status.md
- **Expected vs unexpected errors**: Supported distinction. Expected: thrown `Response`/`data()` (e.g. 404, 401) → `isRouteErrorResponse` branch; **not sanitized** (meant to be rendered); **not passed to `handleError`**. Unexpected: thrown `Error`/values → `instanceof Error` branch; **sanitized in production** (generic message, no stack in the browser; original intact on server); reported to `handleError`. Validation errors should be returned (not thrown) with 4xx. Error boundaries are "not intended for form validation errors or error reporting". Source: docs/how-to/error-boundary.md, docs/api/framework-conventions/entry.server.tsx.md, docs/how-to/form-validation.md
- **Error reporting hooks**: Supported. Server: `export function handleError(error, { request, params, context })` in `entry.server.tsx` — called for errors React Router catches on the server; replaces built-in console logging; skip when `request.signal.aborted` (cancellations); only covers shell render errors when streaming; not called for thrown Responses. Client: `<HydratedRouter onError={(error, { location, params, pattern, errorInfo }) => …}>` — middleware, loader, action and render errors, **once per error** (unlike re-rendering boundaries); `errorInfo` (from `componentDidCatch`) only for render errors. Also instrumentation (§12). Source: docs/how-to/error-reporting.md, docs/api/framework-routers/HydratedRouter.md, docs/api/framework-conventions/entry.server.tsx.md
- **Notable extras**: `useAsyncError()` inside `errorElement`; `useRouteLoaderData("root")` + `useRouteError()` in `Layout` to fork success/error UI. Source: docs/api/hooks/useAsyncError.md, docs/api/framework-conventions/root.tsx.md

## 8. Type safety

- **Typed links and params**: Supported (codegen). `href()` typed against all route paths with their params; `params` typed per route in all `Route.*Args`/props. `<Link to>` is untyped (wrap with `href`). Source: docs/api/utils/href.md, docs/start/framework/routing.md
- **Typed loader/server data → components**: Supported. `Route.ComponentProps` gives typed `loaderData`, `actionData`, `params`, `matches`; types reflect serialization (and `clientLoader.hydrate = true as const` changes the inferred `loaderData` type, hence `as const`). Hooks are less precise (`useLoaderData`, `useRouteLoaderData`). Source: docs/start/framework/route-module.md, docs/explanation/type-safety.md
- **Typed server calls**: Partial. Actions typed through `actionData`/`Route.ActionArgs`; fetchers via generic `useFetcher<typeof loader>()` / `typeof action` (manual `import type`). Middleware typed via `Route.MiddlewareFunction[]`, `Route.ClientMiddlewareFunction[]`; context values typed via `createContext<T>()`. No end-to-end typed RPC except RSC server functions (plain TS imports). Source: docs/how-to/fetchers.md, docs/how-to/middleware.md, docs/api/utils/createContext.md
- **Generated types**: Codegen. Vite plugin generates `.react-router/types/**/+types/<route>.d.ts` from executing `routes.ts`, on `react-router dev` (and custom servers calling `vite.createServer`), regenerating on route config changes. Setup: gitignore `.react-router/`, tsconfig `"include": [".react-router/types/**/*"]`, `"rootDirs": [".", "./.react-router/types"]` so `import type { Route } from "./+types/<file>"` works as a sibling. CLI `react-router typegen [--watch]` for CI (`react-router typegen && tsc`). Generated per route: `LoaderArgs`, `ClientLoaderArgs`, `ActionArgs`, `ClientActionArgs`, `HydrateFallbackProps`, `ComponentProps`, `ErrorBoundaryProps` (+ `MetaArgs`, `HeadersArgs`, `MiddlewareFunction`, `ClientMiddlewareFunction` used in docs). Source: docs/explanation/type-safety.md, docs/how-to/route-module-type-safety.md, docs/api/other-api/dev.md
- **Typed search params**: Not supported (not found; `URLSearchParams` only).
- **Notable extras**: `verbatimModuleSyntax` recommended for type-only auto-imports; `createRoutesStub` is incompatible with `Route.*` types (testing). Source: docs/how-to/route-module-type-safety.md, docs/start/framework/testing.md

## 9. Metadata & SEO

- **Head/meta management per route**: Supported, two ways.
  1. **React 19 built-ins (recommended)**: render `<title>`, `<meta>`, `<link>` anywhere in route components; React hoists them to `<head>`.
  2. **`meta` export** (still supported): `meta(args) => MetaDescriptor[]`, rendered by `<Meta/>` in root `<head>`. Only the **last (deepest) matching route's** array is used — **replaced, not merged** (compose manually via `matches`). Descriptor forms: `{ title }` → `<title>`; `{ name, content }` / `{ property, content }` → `<meta>`; `{ charSet }` etc.; `{ "script:ld+json": object }` → `<script type="application/ld+json">` with stringified object; `{ tagName: "link", rel: "canonical", href }` → `<link>` (for SEO links; stylesheets/icons belong in `links`). Args (`Route.MetaArgs`): `loaderData`, `matches` (each with `loaderData`); `params`, `location`, `error` (from memory, unverified). v8 removed the old `data` arg.
  `links` export → `LinkDescriptor[]` (`rel`, `href`, `type`, `as`, …) aggregated across all matched routes by `<Links nonce? crossOrigin?>`.
  Source: docs/start/framework/route-module.md, docs/how-to/meta.md, docs/api/components/Meta.md, docs/api/components/Links.md, docs/upgrading/v7.md
- **Metadata derived from loaded data**: Supported (`meta({ loaderData, matches })`; or React elements using `loaderData`). Source: docs/upgrading/v7.md
- **Sitemap / robots / manifest generation**: Not supported built-in. Implement as resource routes (fs-routes escaping example `sitemap[.]xml.tsx` → `/sitemap.xml`). Source: docs/how-to/file-route-conventions.md
- **Open Graph image generation**: Not found in docs (resource routes could return images).
- **Canonical, etc.**: Via `meta` `tagName: "link"` or React `<link rel="canonical">`. Source: docs/how-to/meta.md
- **Notable extras**: Status codes for SEO (404 via `throw data`, catch-all route returns 200 unless changed); prerendering for static SEO pages; `handle` for breadcrumb metadata. Source: docs/how-to/file-route-conventions.md, docs/how-to/pre-rendering.md, docs/how-to/using-handle.md

## 10. Assets & styling

- **Image optimization**: Not supported / not found (no image component or pipeline; Vite static asset handling only; `--assetsInlineLimit` default 4096 bytes). Source: docs/api/other-api/dev.md, docs/explanation/styling.md
- **Font optimization**: Not found in docs.
- **Third-party script loading**: Not supported as a framework feature (no `<Script>` strategy component). `<Scripts>` renders only the app's client runtime (accepts `scriptProps` such as `nonce`, `crossOrigin`). Options: `links` export (`rel: "preload"`), React 19 elements, `.client` modules for browser-only SDKs, conditional render in root `Layout`. Source: docs/api/components/Scripts.md, docs/start/framework/route-module.md, docs/api/framework-conventions/client-modules.md, docs/api/framework-conventions/root.tsx.md
- **CSS support**: Supported via Vite ("mostly just Vite's styling story"; no separate CSS pipeline). Three patterns: (1) side-effect imports (`import "./app.css"` in root or routes/components), (2) `links` export with `import href from "./x.css?url"` → real `<link rel="stylesheet">` via `<Links/>`, (3) React 19 `<link rel="stylesheet">` in components (hoisted). CSS Modules, Tailwind (in default templates), PostCSS, Sass, Vanilla Extract via standard Vite setup. Scoped styles / CSS-in-JS: no special support documented. Root `Layout` prevents FOUC from remounting `<Links>`. Source: docs/explanation/styling.md, docs/start/framework/deploying.md, docs/api/framework-conventions/root.tsx.md
- **MDX/Markdown as pages**: Partial. Documented only for RSC framework mode (MDX routes with `@mdx-js/rollup` ≥3.1.1). Non-RSC MDX routes via the MDX Rollup/Vite plugin are not documented here (likely works, from memory, unverified). Source: docs/how-to/react-server-components.md
- **Notable extras**: Route-level `links` lets stylesheets be per-route and preloaded with route modules; prefetching (`<Link prefetch>`) also prefetches route CSS/modules (from memory, unverified for CSS). Source: docs/explanation/styling.md

## 11. Build output & deployment

- **Output modes**: `react-router build` (sets `NODE_ENV=production`, minifies) produces:

  | Mode | Config | Output |
  |---|---|---|
  | Server | `ssr: true` (default) | `build/client` (assets, prerendered pages) + `build/server/index.js` (server build exporting the handler; filename `serverBuildFile`, format `serverModuleFormat: "esm"` (default) / `"cjs"`) |
  | SSR + partial prerender | `ssr: true, prerender` | above + `.html`/`.data` files in `build/client` |
  | Static export | `ssr: false, prerender` | `build/client` only (+ SPA fallback html for non-prerendered paths) |
  | SPA | `ssr: false` | `build/client` with `index.html`; no server build generated |
  | API-only (unstable) | `ssr: "unstable_api-only"` | `build/client` (shell/prerendered) + runtime server for data/manifest |
  | RSC (unstable) | RSC plugin | `build/server/index.js` default export `(request) => Promise<Response>` (adapt to Node via `@remix-run/node-fetch-server` `createRequestListener`) |

  Directories: `appDirectory` (default `"app"`), `buildDirectory` (default `"build"`). Source: docs/api/framework-conventions/react-router.config.ts.md, docs/how-to/pre-rendering.md, docs/how-to/spa.md, docs/start/framework/rendering.md, docs/how-to/react-server-components.md, docs/api/other-api/dev.md
- **Supported runtimes**: Node (officially all Active LTS versions + latest minor of Maintenance LTS: 24.x, 22.22.x as of 2026-06); Cloudflare Workers (official adapter + `@cloudflare/vite-plugin`; custom `entry.server` required); AWS Lambda via Architect adapter; any Fetch-API runtime via `createRequestHandler`. Bun/Deno mentioned only re `AsyncLocalStorage` availability (no dedicated docs). **Per-route runtime choice**: Not supported; `serverBundles` can split routes into separate server bundles (host routing layer needed) which enables per-bundle deployment but not a runtime switch. Source: docs/api/other-api/adapter.md, docs/upgrading/v7.md, docs/how-to/middleware.md, docs/how-to/server-bundles.md
- **Adapters / presets for hosts**: Official adapters: `@react-router/express`, `@react-router/architect` (v8 uses `event.requestContext.domainName` for host), `@react-router/cloudflare`; utilities `@react-router/node` (e.g. `createReadableStreamFromReadable`); app server `@react-router/serve`. All share `createRequestHandler({ build, getLoadContext?, mode? })`. Host-maintained templates/guides (not official adapters): Vercel, Cloudflare, Netlify, EdgeOne Pages, DeployHQ, Hostinger; official Docker templates (`default`, `node-custom-server`, `node-postgres`) for AWS ECS, Cloud Run, Azure Container Apps, DO, Fly.io, Railway. **Presets API** (`presets: Preset[]`): presets can only (a) contribute config (merged in order; user config wins) and (b) validate the resolved config via `reactRouterConfigResolved`; intended for hosting integrations published to npm. `buildEnd({ buildManifest, reactRouterConfig, viteConfig })` hook. `serverBundles({ branch })` (branch items: `id`, `path`, `file`, `index`; not called for pathless layouts) → bundle ID directories; `buildManifest` exposes `serverBundles`, `routeIdToServerBundleId`, `routes`. Source: docs/api/other-api/adapter.md, docs/start/framework/deploying.md, docs/how-to/presets.md, docs/how-to/server-bundles.md, docs/api/framework-conventions/react-router.config.ts.md
- **Config-level headers, redirects, rewrites, trailing slash, base path**: Headers/redirects/rewrites: Not supported in config (use `headers` export, middleware, `entry.server`, loaders; host config such as `_redirects`). Trailing slash: no normalization option documented; `.data` URLs are trailing-slash aware in v8 (inferred default). Base path: `basename`. Source: docs/api/framework-conventions/react-router.config.ts.md, docs/upgrading/v7.md, docs/how-to/spa.md
- **Standalone / self-contained output**: Not found (server build still needs `node_modules` deps; Docker templates provided). Source: docs/start/framework/deploying.md
- **Skew protection**: Partial. Lazy route discovery sends the client manifest `version`; on mismatch the default recovery reloads (navigation → reload destination; fetcher → reload current document; eager discovery → warn). Experimental `future.unstable_customRouteDiscovery` + `unstable_useRouteDiscovery({ onManifestMismatch })`: handlers (reverse registration order, `event.stopPropagation()`, `event.defaultBehavior()`, `event.loadAllRoutes()`), `discoverRoutes(paths, { signal })` → `{type:"success"|"version-mismatch"|"aborted"}`, `loadAllRoutes()` loads the running client's versioned full manifest (requires old assets retained on CDN and API-compatible loaders/actions), shared `state` `partial → loading → complete`. No server-side multi-version routing. Source: docs/how-to/route-discovery.md, docs/api/hooks/useRouteDiscovery.md, docs/explanation/lazy-route-discovery.md
- **Notable extras**: `build` CLI flags (`--assetsInlineLimit` 4096, `--minify` esbuild|terser|bool, `--sourcemapClient`/`--sourcemapServer` bool|inline|hidden (default false), `--mode`, `--emptyOutDir`, `--profile`, `--logLevel`); custom server compiled into the server build via `environments.ssr.build.rollupOptions.input` (Vite Environment API); `allowedActionOrigins` overridable at runtime on the build object. Source: docs/api/other-api/dev.md, docs/upgrading/v7.md, docs/api/framework-conventions/react-router.config.ts.md

## 12. Dev tooling & observability

- **Dev server and HMR**: Supported. `react-router dev` (Vite) with HMR (React Fast Refresh) and **Hot Data Revalidation (HDR)**: server-code changes affecting the current page re-run loaders without reload. Route exports (`meta`, `links`, `loader`, `action`, `headers`, …) are HMR-compatible; any user-defined extra export from a route module forces a full reload; Fast Refresh limits (class components, anonymous components, hook add/remove, destructured-key renames) apply. Flags: `--host`, `--port`, `--strictPort`, `--open`, `--cors`, `--force`, `--mode`, `--config`, `--logLevel`, `--clearScreen`, `--profile`. Dev/preview servers derive protocol from `X-Forwarded-Proto` (host from `Host`); warned not to expose publicly. `future.unstable_optimizeDeps` feeds client entry + route modules to Vite's dep optimizer. Custom servers can run Vite in middleware mode (`--conditions development`). Source: docs/api/other-api/dev.md, docs/explanation/hot-module-replacement.md, docs/upgrading/future.md, docs/api/other-api/adapter.md
- **Error overlay**: Not found in docs (Vite's overlay presumably applies, from memory, unverified). Dev shows unsanitized server errors in error boundaries (production sanitizes). Source: docs/how-to/error-boundary.md
- **Devtools**: Not found in docs.
- **Type generation commands**: `react-router typegen [--watch] [--config] [--mode]`; automatic during dev. Source: docs/api/other-api/dev.md
- **CLI scaffolding / generators**: `npx create-react-router@latest [dir] [--template remix-run/react-router-templates/<name>]`; `react-router reveal [entry.client|entry.server|entry.rsc|entry.ssr] [--no-typescript]` ejects default entries; `react-router routes [--json]`; `react-router build`, `dev`, `typegen`. No route/component generators. Source: docs/start/framework/installation.md, docs/api/other-api/dev.md, docs/how-to/react-server-components.md
- **AI-agent support**: Minimal. `docs/start/modes.md` includes an "API + Mode Availability Table" described as "mostly for the LLMs". No llms.txt, AGENTS.md, bundled docs or MCP server found in docs.
- **Instrumentation / OpenTelemetry hooks**: Supported, stable (no prefix). `export const instrumentations = [...]` in `entry.server.tsx` (server) and `<HydratedRouter instrumentations>` in `entry.client.tsx` (client). Levels: `handler.instrument({ request(handleRequest, { request, context }) })` (server; result has `statusCode`, `meta`), `router.instrument({ navigate(call, { to, currentUrl }), fetch(call, { href, currentUrl, fetcherKey }) })` (client), `route.instrument({ loader, action, middleware, lazy })` (both; info `{ params, request, context, pattern }`). `call*()` returns `{ status: "success"|"error", error }` and never throws; errors in instrumentation code are swallowed. **Read-only** (cannot alter args/results). `meta` = `{ url, pattern, params }` (undefined for manifest requests/POP numeric navigations; describes original target on redirects). Composition: array wraps in nesting order. Docs include an OpenTelemetry tracer example and client performance tracking. Source: docs/how-to/instrumentation.md
- **Server error reporting hooks**: `handleError` in `entry.server.tsx`; client `onError` on `HydratedRouter` (§7). Source: docs/how-to/error-reporting.md
- **Web vitals reporting**: Not found in docs.
- **Notable extras**: `v8_passThroughRequests` lets handlers distinguish document vs `.data` requests for observability (`request.url` ends with `.data`). `routes --json` exposes the route tree to tooling. Source: docs/upgrading/v7.md, docs/api/other-api/dev.md
